# 로터리 진입구간 CTRV vs CTRA 평가 요약

## 측정 범위

로터리 미션의 실제 필요 범위(ego 진입 직전, 다가오는 차량 1대 + 멀어지는 차량 1대의 예측경로)만 좁혀서 평가. 기존 CTRV vs CTRA 비교(전체 로터리 궤적·모든 시점 대상)보다 범위를 좁힌 재평가.

| 항목 | 값 |
|---|---|
| 대상 bag | sensor_cam_raw_roundabout1.bag |
| 로터리 원 피팅 | 중심(-53.30, 208.62), 반지름 143.24m |
| 회전방향 | CW |
| ego 상태 | 진입 지점에 정차(속도 0, Gear P) — 고정 위치를 게이트로 사용 |
| 샘플 수 | 접근 285개 / 이탈 284개 (합계 569개) |

## 평가 지표 정의 (ADE / FDE)

| 지표 | 정의 | 의미 |
|---|---|---|
| FDE(h) | t+h 시점 예측 위치 vs 실제 위치, 한 점만의 오차 | "h초 뒤 상대 차량이 어디 있는가"에 직접 대응 |
| ADE(h) | 0~h 구간을 잘게 나눈 중간 시점들의 오차를 평균 | "h초 동안 예측 경로 전체가 실제 경로를 따라가는 정도" |

현재 표의 모든 수치는 **FDE(h) 기준**(중간 경로는 미포함). ADE(h)는 아래 "ADE vs FDE" 절 참고(2026-08-01 계산 완료).

판단 기준(초안): "3.0m 이내 오차를 90% 확률로 보장"을 FDE(h) p90에 적용해 만족하는 최대 h를 채택.

## CTRV vs CTRA (접근+이탈 합산, 단위: m)

**2026-08-02 정정:** 아래 표는 `eval_entry_zone_ctrv_ctra.py`의 가속도 추정 버그(직전 프레임 속도 `v_prev`는 항상 양수로 두고, 현재 프레임 속도 `v_cur`만 헤딩 기준 부호를 매기던 비대칭 처리 — `eval_model_ablation.py`/`eval_final_horizon_decision_ctra.py`는 처음부터 양쪽 다 부호를 매겨서 이 버그가 없었음)를 수정한 뒤 재계산한 값으로 교체함. 이 버그는 두 프레임 사이에서 투영 속도 부호가 뒤집히는 표본에서 가속도가 실제보다 수백~수천 배 크게 추정되게 만들었고, 이게 이전에 적었던 "2.0s에서 CTRA p90=963.6m/p95=1138.3m" 수치와 "오메가가 작을 때 1/오메가² 항이 노이즈를 증폭시킨다"는 설명의 원인이었음(팀원이 Codex로 따로 찾아서 수정 제안, 실제 버그가 맞아서 본 저장소에도 반영함 — 수정 전 최악 표본의 오메가는 0.466 rad/s로 전혀 작지 않았고, 원인은 순수히 이 가속도 버그였음). CTRV는 가속도를 안 쓰므로 버그 영향 없이 수치 그대로임.

| 0.6 | 2.975 / 0.184 / 6.938 / 6.960 | 3.156 / 0.184 / 6.931 / 6.950 |
| 0.9 | 4.151 / 0.303 / 10.369 / 10.416 | 4.568 / 0.301 / 10.355 / 10.393 |
| 1.2 | 5.067 / 0.434 / 13.778 / 13.823 | 5.832 / 0.428 / 13.743 / 13.784 |
| 1.5 | 5.730 / 0.581 / 17.144 / 17.191 | 6.949 / 0.575 / 17.085 / 17.134 |
| 2.0 | 5.838 / 0.830 / 22.680 / 22.732 | 8.162 / 0.820 / 22.563 / 22.618 |

(0.5/1.7/3.0s는 아직 수정된 스크립트로 재실행 전 — 필요하면 재실행해서 채울 것)

**결론 (수정): CTRA는 mean에서만 CTRV보다 뚜렷이 나쁨(예: 2.0s에서 8.16m vs 5.84m). p50/p90/p95는 오히려 CTRA가 CTRV와 거의 같거나 근소하게 더 낮음(2.0s p90: CTRA 22.56m vs CTRV 22.68m).** 즉 "CTRA가 전 percentile에서 압도적으로 나쁘다"는 기존 결론은 틀렸음 — 실제로는 평균적으로만 CTRA가 약간 더 손해고, 안전마진에 직결되는 p90/p95 최악의 경우는 두 모델이 비등함. 그래도 mean이 꾸준히 나쁘고 CTRV를 바꿀 실익이 없어 CTRV 채택 결론 자체는 유지하지만, 근거로 이 표의 수백 배 격차를 인용하면 안 됨(그 격차는 버그였음). CTRV 채택의 실제 근거는 `docs/ctrv_vs_ctra_decision_summary.md`의 원본 표(버그 없는 스크립트로 계산됨, +0.2~+9.6% 수준의 모자란 격차)임.

- 0.3~2.0s 전 구간: 이탈 차량 오차가 접근 차량보다 뚜렷하게 큼. 특히 median 자체가 이미 p90 수준까지 올라가 있어 "가끔 튀는 게 아니라 대부분의 순간에 크게 벗어남".
- 3.0s만 역전: 이탈 차량이 이미 원형 구간을 벗어나 직선 구간으로 진입한 표본이 섞여 CTRV(직진 시 정확)가 오히려 잘 맞은 것으로 추정.
- 실사용 horizon 범위(0.3~1.7s)에서는 접근 차량 예측이 안정적으로 정확하고, 이탈 차량 쪽이 병목.

## 실사용 horizon 선택: threshold별 커버리지 기준 (2026-08-01, 1차 3m 단일 → 2차 1/2/3/5m 다중 비교로 보강)

목표: 판단/제어가 요구하는 2.0s에 가까운 값이 "실사용 가능한지"를 90/95% 안전마진 기준보다 느슨한 "X m 이내 몇 %" 기준으로 확인.

**주의(생존편향, 최초 시도에서 발견):** horizon별로 그냥 커버리지를 계산하면, horizon이 길어질수록 `t+h` 시점 GT가 없는 표본(다음 텔레포트/궤적 끝에 걸리는 표본, 특히 이탈 차량에서 심함 — n 284→129, 55% 손실)이 먼저 탈락해서 "표본이 쉬워져서 좋아 보이는" 착시가 생김. `filter_samples_with_full_horizon()`로 **모든 horizon에서 동일한 표본집합(전체 n=399, 접근 n=270, 이탈 n=129)**을 쓰도록 고정해서 재평가함.

|---|---|---|---|---|---|---|
| 1m | 87.7% | 69.9% | **-17.8%p** | 53.5% | 38.8% | **-14.7%p** |
| 2m | 87.7% | 86.6% | -1.1%p | 53.5% | 51.2% | -2.3%p |
| 3m | 87.7% | 87.4% | -0.3%p | 53.5% | 53.5% | 0%p |
| 5m | 87.7% | 87.7% | 0%p | 53.5% | 53.5% | 0%p |

**결론 (threshold에 따라 답이 갈림):**
- **3~5m 기준(차선 단위 판단이면 충분)이면 2.0s는 손실이 거의 없음** — 접근/이탈 모두 손실 0~0.3%p. 판단/제어가 원하는 2.0s를 그대로 채택해도 됨.
- **1m 기준(정밀 위치 요구)이면 2.0s는 비쌈** — 접근 -17.8%p, 이탈 -14.7%p로 확실히 나빠짐. 이 경우 1.0~1.3s 근처가 현실적 타협점(전체 커버리지가 아직 크게 안 깎이는 구간).
- 2m 기준은 그 중간(1.6s 근처부터 소폭 하락, 실사용엔 지장 없는 수준).
- **이탈(departing) 차량은 모든 threshold에서 구조적으로 약함** — 애초에 절반가량이 게이트 통과 직후 궤적 전환(회전→직진 등) 구간이라, 느슨한 기준(3~5m)에서는 horizon을 늘려도 더 나빠지진 않지만 53.5%라는 상한 자체는 그대로 남음. horizon 조정으로 해결되는 문제가 아님.
- 기존 "0.3s @ 90/95% 안전마진" 결론(2절)은 더 엄격한 기준이라 그대로 유효. 이번 결과는 그보다 느슨한 실사용 기준에서, **판단/제어가 요구하는 실제 정밀도(1m vs 3~5m)에 따라 2.0s 채택 여부가 갈린다는 것**이 핵심 발견.

## ADE vs FDE 비교 (2026-08-01 추가)

ADE(h) = 0~h를 0.1s 간격으로 쪼갠 중간 시점들의 오차 평균 ("경로 전체가 실제를 얼마나 잘 따라가는가"). FDE(h) = t+h 한 점만의 오차 ("h초 뒤 정확히 어디 있는가"). 동일 표본집합(전체 n=399/접근 270/이탈 129, 생존편향 제거) 기준.

| horizon(s) | FDE mean | ADE mean | ADE/FDE |
|---|---|---|---|
| 0.3 | 0.87 | 0.59 | 0.67 |
| 1.0 | 2.88 | 1.59 | 0.55 |
| 1.5 | 4.35 | 2.31 | 0.53 |
| 2.0 | 5.84 | 2.95 | 0.51 |

**ADE/FDE 비율이 horizon이 길어질수록 계속 낮아짐(0.67→0.51)** — 오차가 경로 내내 고르게 벌어지는 게 아니라 **horizon 끝부분에 집중적으로 쌓인다**는 뜻. CTRV가 초반엔 잘 맞다가 시간이 지날수록 급격히 벌어지는 전형적인 패턴.

**중요한 함정:** threshold별 커버리지를 ADE로 다시 보면 결과가 크게 달라짐.

| 기준(1m) | 0.3s | 2.0s |
|---|---|---|
| FDE 커버리지(전체) | 76.6% | **59.8%** (크게 하락) |
| ADE 커버리지(전체) | 76.6% | **77.2%** (거의 그대로) |

즉 **ADE만 보면 "2.0s도 1m 기준으로 문제없다"는 착각을 하게 됨** — 경로 초반의 작은 오차들이 평균에 섞여서 "2.0s 뒤 정확한 위치가 크게 틀렸다"는 사실을 가려버리기 때문. **판단/제어가 "h초 뒤 상대 차량이 정확히 어디 있는가"(충돌 판단, gap 계산 등)를 쓴다면 FDE가 맞는 지표**이고, "예측 경로 전체가 실제 경로와 얼마나 겹치는가"(경로 기반 연속 충돌 체크 등)를 쓴다면 ADE가 맞는 지표. **이 프로젝트는 특정 시점의 상대위치 판단이 목적이므로 FDE를 기준으로 삼아야 하며, 1m 정밀도가 필요하다면 3절의 FDE 기준(2.0s에서 -17.8%p 손실) 결론이 유효함.**

## 최종 결정 (2026-08-01, 하이웨이 재평가 반영해 2.0s → 1.5s로 수정)

처음엔 로터리만 보고 **2.0s를 채택**했었음(3.0m 기준 손실 0~0.3%p로 사실상 손실 없음). 이후 `mission_switching` 노드는 만들지 않고 미션 무관 **단일 고정 horizon**을 쓰기로 결정하면서, 같은 방식으로 하이웨이도 재평가함(`docs/highway_ctrv_ctra_summary.md`). 그 결과 **2.0s는 하이웨이에서는 손실이 있음**(3.0m 커버리지 94.3%→84.7%, -9.6%p, 1.6s부터 하락 시작)이 확인됨.

반면 **1.5s는 로터리·하이웨이 둘 다에서 3.0m 커버리지 손실이 0**(로터리 87.7%→87.4%대 유지, 하이웨이 94.3% 그대로)인 가장 긴 값. 미션 무관 단일 horizon이라는 목표에 맞춰 **최종적으로 1.5s를 채택**함. (2.0s와 큰 차이는 아니고 애초에 "2.0s에 가까운 실사용 가능한 값"이 목표였으므로, 이 변경은 목표에서 벗어나지 않음.)

**리스크로 남기는 것:** 나중에 판단팀 요구 정밀도가 1m 수준으로 확인되면 이 결정은 재검토 필요(1m 기준으로는 로터리도 1.5s 근방부터 손실이 커짐, 그때는 1.0~1.3s가 대안). 또한 이탈(departing) 차량은 horizon 선택과 무관하게 53.5% 상한에 고정된 구조적 약점이므로, horizon 채택과 별개로 판단/제어팀에 "이탈 차량 예측은 약 절반만 신뢰 가능"이라는 사실을 전달해야 함.

## 남은 항목

- highway 시나리오 재평가 완료 (`docs/highway_ctrv_ctra_summary.md`) — 이 문서의 2.0s 결론을 뒤집는 계기가 됨.
- 이탈(departing) 차량의 구조적 53.5% 커버리지 한계 — 원인(궤적 전환 구간) 특정은 했으나 개선책은 아직 없음. 판단팀과 이 한계를 어떻게 다룰지(예: 이탈 차량은 더 보수적으로 처리) 논의 필요.
- 판단/제어팀에 실제 요구 정밀도 확인 필요 — 1m 기준일 경우 1.5s도 재검토 대상.
