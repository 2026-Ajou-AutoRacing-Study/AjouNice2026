# 대회용 LC: 방향지시 대기 제거와 조기 시작 후보 탐색

## 적용한 정책

`trajectory.min_prepare_duration=0`을 대회용 signal-free 정책으로 사용한다.
이 설정에서는 방향지시 경과시간을 준비 시간에서 사용하지 않는다.
일반 속도에서는 준비 시간 0, 0.5, …, 4초를 이른 순서로 검사한다.
저속에서는 최소 LC 속도까지 물리적으로 가속하는 데 필요한 시간부터 시작한다.
가속할 수 없거나 최대 준비 시간 안에 준비할 수 없으면 후보를 만들지 않는다.
최소 준비 시간이 양수인 기존 설정은 기존 방향지시 정책을 유지한다.

최대 4초는 강제 대기가 아니라 대체 후보의 탐색 범위로 남긴다.
이 값은 목표 차로 시작점에 대한 lookahead에도 쓰이므로 0으로 만들지 않는다.
즉시 LC는 순간 횡이동이 아니라 현재 위치에서 횡이동 궤적을 시작한다는 의미다.
진행 중 승인된 LC를 임의로 갈아 끼우지 않는다.

## 샘플링

- 횡가속: 전 속도 구간에서 최소 1.0, 최대 6.5 m/s².
- `lat_acc_sampling_num=11`: 양 끝 포함 12개, 0.5 m/s² 간격.
- 일반 PathShifter와 Frenet 모두 횡가속 샘플을 사용한다.
- 종가속 분할 수는 후속 수정에서 20으로 증가했다. 양 끝 및 0 포함 최대 22개다.
- 준비 시간 9개 × 종가속 22개 × 횡가속 12개 = 2376개는 필터 전 조합 예시이며,
  실제 생성/안전 검사 개수 보장이 아니다. 좌우/모듈 인스턴스별로도 다르다.
- Frenet은 준비 조건 하나씩(최대 횡가속 후보 12개) 생성·검사하고 안전하면 종료한다.
  모든 늦은 후보를 먼저 생성하다가 검사 시간 예산을 소모하지 않도록 했다.
- 기존 50 ms 탐색 예산을 유지한다. 각 생성 배치를 선점 중단하는 hard real-time
  보장은 아니며, 실제 전체 BPP 주기 성능은 폐루프에서 추가 확인해야 한다.

## 제거/보완

- signal-free 정책에서 방향지시 경과시간으로 인한 준비 지연 제거.
- 멀리서는 준비 시간 하나만, 종료부에서만 여러 시간을 보던 제한 제거.
- 준비거리만 같다는 이유로 다른 종가속 실행 후보를 건너뛰던 사전 가지치기 제거.
  후속 준비+LC 길이 중복 판정은 유지한다.
- 0 m 준비 경로는 ego의 경로상 투영점을 삽입해 정확히 그 위치에서 끝낸다.
  기존 clipping이 다음 경로 점까지 반올림하는 동작을 피한다.
- Frenet의 0/비유한 실행 시간은 다항식 생성 전에 거부한다.
- 충돌/RSS, 경계, 차량 footprint, 금지 구간, 실행/승인 안전 조건은 우회하지 않는다.
  지도, preferred, requester는 수정하지 않는다.

## 후속: 가감속 LC 샘플링

- `min_prepare_duration=0` 대회 정책에서는 차로 끝 부근뿐 아니라 일반 구간에서도
  종가속 전체 범위를 탐색한다. 최대 가속, 최대 감속, 다음 가속, 다음 감속 순서로
  양쪽을 번갈아 검사한다. 최초 안전 후보에서 종료하며 최속 비용 최적화는 아니다.
- 실제 확인한 상한은 +3.7 m/s²이다. LC min=-8.0이지만 BPP normal min=-6.0이므로
  교집합은 -6.0~+3.7이다. 이 제한은 변경하지 않았다. 20분할 간격은 약 0.485이다.
- 준비/실행 종료 속도 및 경로/전역 속도 상한에 의해 유효 가감속 범위는 줄어든다.
  충분한 속도·거리 여유가 있을 때에만 최대 가속/감속을 LC 내내 사용할 수 있다.
- 일반 구간에서 음의 LC 종가속을 0으로 바꾸던 정책을 대회 모드에서 제거했다.
  PathShifter의 음의 종가속 무시도 수정하고, 종료 전 정지하는 불가능한 이동은 거부한다.
- 일반 LC 출력은 실행 위치별 속도를 반영한다. Frenet은 초기/종료 가속·종료 속도·
  이동거리를 같은 유효 가속으로 계산하고, 참조 경로 끝을 넘는 다항식은 거부한다.
  감속 Frenet 출력을 종료 속도로 일괄 낮추던 처리도 대회 모드에서 제거했다.
- 충돌 예측에서 속도와 거리를 같은 적분으로 계산한다. 정지 후 역행하는 수식과
  승인 후 음의 측정 가속 제거/누적 시간 중복 적분을 대회 모드에서 수정했다.
- 기존 결정 로그에 prepare_t, lc_t, prepare_a, lc_a를 추가했다.
- 공통 회귀시험 75개, LC utils 14개, scene 9개(기존 disabled 1개)가 통과했다.
  양 끝값, 0, 그리드 간격, 실제 +/- 가속 실행, 속도 경계, 예측 위치/속도,
  제동 정지 후 비역행, 감속 PathShifter 모양/불가능 거리 거부를 검사한다.
- 개발 라이브러리로 19:15 백 95~113초를 독립 재생한 첫 결과는 path 159개,
  geometry 1098개, 명시적 time-limit 로그 0개였다. 모든 배치의 시간 예산 충족이나
  실제 차량 가감속/추월 성공을 보증하는 수치가 아니다.
- 하위 속도 계획기·제어기의 제한은 그대로 적용된다. 풀가속 후보의 존재는 항상
  풀스로틀을 명령하거나 해당 후보가 상대차보다 빠르다고 최적 선택한다는 뜻이 아니다.

## 실제 launch 설정 경로 수정 및 조기 preferred 변경

앞선 설치 확인은 개별 lane_change.param.yaml만 대상으로 했으므로 불완전했다.
실제 competition_planning.launch는 tier4_planning_launch의 behavior_planning.launch를
거쳐 통합 behavior_path_modules.yaml을 로딩한다. 따라서 기존 상태에서는 재시작만
해도 min_prepare=2, lon_samples=5, lat_samples=3, lat_min=2.5, lat_max=8이 유지됐다.

통합 소스 및 planning_ws/install_isolated 설치본의 LC 값을 각각 0, 20, 11,
1.0, 6.5로 수정했다. 실제 competition_planning.launch의 --dump-params 출력에서
다섯 항목을 검증했다. 개별 YAML 강제 주입 재생이 아니라 실제 launch 구성 확인이다.

Route A/B expected_path_lanelet_ids의 201470,200130을 201469,200127로 교체했다.
병목 접근은 200187 -> 201469 -> 200127 -> 201473 -> 201439를 선호한다.
200360 이후의 선호 경로와 지도 및 primitive 집합은 변경하지 않았다.
base_ws/install_aw149 및 install_planning_addons의 requester 경로 YAML도 동기화했다.
이는 조기 왼쪽 차로 선호를 뜻하며, 특정 좌표의 LC 강제 실행이나 폐루프 성공 보장은 아니다.

현재 실행 스택을 강제 종료하거나 경로를 재발행하지 않았다. 사용자가 플래닝 전체를
재시작하고 Route A부터 새로 요청해야 새 requester 설정과 LC 정책이 함께 활성화된다.
