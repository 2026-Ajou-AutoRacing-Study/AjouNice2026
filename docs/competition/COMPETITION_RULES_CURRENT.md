기준은 [사용자가 전달한 규정집 v1.2 원문](261015_대회_규정_v1.2_원문.md)이다.

대회 운영측의 변경·현장 판단 조건은 해당 조항과 함께 적용한다.

첨부에는 3-1 미션 지도 그림과 체크포인트 상세 링크·좌표가 포함되지 않았다.
체크포인트 좌표·지도 파일 버전·UDP 포트 번호를 이 규정 텍스트만으로 확정하지 않는다.

## 운영과 수정 제한

- 참가팀 PC는 데스크톱·서버·워크스테이션·노트북이 허용되며 OS는 자유다.
- 각 팀은 독립된 **싱글플레이**에서 같은 시나리오로 2회 주행한다.
- MORAI Client PC와 참가팀 알고리즘 PC는 LAN-to-LAN으로 직접 연결한다.
  Client는 시뮬레이터·판정·녹화 프로그램을, 참가팀 PC는 자율주행 알고리즘을 실행한다.
- PC 제출 이후 코드·주석·파라미터·**실행 명령의 파라미터도 수정 불가**다.
  예외는 네트워크 설정의 IP·Port 등이다.
- 코드·모델 실행 이후 Operator는 PC를 조작할 수 없다.
- PC 제출 지연은 각 주행 차시별 30초 패널티다.
- 팀 PC 성능에 따른 네트워크·센서 지연은 운영측에서 보정해 주지 않는다.
  Client의 판정·녹화 부하로 전송이 지연될 수 있어 센서 사양과 코드를 경량화하도록 권장한다.

초기 상태는 운영 요원이 시나리오를 로드하고 Ego를 keyboard 모드·P 기어로 설정한다.
센서·네트워크 연결과 판정 준비를 확인한 뒤 팀 알고리즘을 실행하며, 차량 출발에
맞춰 판정 프로그램을 시작한다. 자동 ExternalCtrl 전환 시점은 이 본문만으로
추가 확정하지 않는다.

## 센서 제한

모든 외부 센서 연결은 UDP다. 사용하지 않는 센서의 네트워크는 Disconnect할 수 있다.

| 센서 | 최대 개수 | 허용 범위 |
|---|---:|---|
| GPS | 1 | 최대 30 Hz |
| IMU | 1 | 최대 50 Hz |
| 3D LiDAR | 1 | VLP16, Intensity, 최대 15 Hz. 권장 10 Hz 이하 |
| Camera | 4 | 최대 30 Hz, 아래 고정 3대와 추가 1대 |

**2026년에는 GPS·IMU에 Noise를 인가하지 않는다.** 이는 GNSS 출력 양자화나
GPS 음영·전송 지연이 없어진다는 뜻은 아니다.

| 고정 카메라 | 위치 x/y/z, m | 각도 roll/pitch/yaw, ° | 최대 해상도 | FOV |
|---|---|---|---|---|
| Front | `1.9 / 0 / 1.2` | `0 / 2 / 0` | `1280×720` | `90°` |
| Left | `1.15 / 0.65 / 1.2` | `0 / 10 / 70` | `640×480` | `130°` |
| Right | `1.15 / -0.65 / 1.2` | `0 / 10 / 290` | `640×480` | `130°` |

고정 카메라의 위치·각도·FOV는 변경 불가이며 해상도는 표의 최대값 이하로 줄일 수 있다.
나머지 1대는 규정 범위 내 자유 배치다. 카메라 공통 항목은 Model=Camera,
Ground Truth=None, Compression Ratio 자유, Viz Bounding Box 2D/3D 해제다.

## 허용 네트워크와 상태 입력

허용된 네트워크 외 사용은 실격 처리한다. 규정 2-8의 허용 항목은 다음 7개다.

| UDP 항목 | 사용 범위 |
|---|---|
| Ego Ctrl Cmd | Accel·Brake·Steer·Gear·CtrlMode. **cmd type=1(accel/brake), ctrl mode=2** |
| CollisionData | 충돌 여부 |
| Competition Vehicle Status | 자세, x 방향 속도, 각속도, 제어 입력값(accel/brake/steer) 등 |
| GPS | GPS 센서 |
| IMU | IMU 센서 |
| Camera | Camera 센서 |
| 3D LiDAR | LiDAR 센서 |

Competition Vehicle Status에는 다음 정보가 제공되지 않는다.

- `pos_x/y/z`, `vel_y/z`, `accel_x/y/z`.
- `tire_lateral_force_fr ~ rr`, `side_slip_angle_fl ~ rr`,
  `tire_cornering_stiffnesss_fl ~ rr` (원문 표기). 이 목록만으로 FL 횡력의 제공 여부를 추론하지 않는다.

Ego Detail Status·Ego Vehicle Status·Get TrafficLight Status는 **판정 전용이며
참가팀 사용 불가**다. Object Info도 허용 7개 목록에 없으므로 개발용 GT 객체
입력을 대회용으로 가져가지 않는다. 미제공 필드에 0이 채워져 있어도 실측 정보로
사용할 근거가 되지 않는다.

허용 UDP 정보를 참가팀 PC 내부 ROS 토픽으로 전달하는 것과, 시뮬레이터의
미허용 채널을 추가 수신하는 것은 구분한다. `/competition/raw_twist` 같은 내부
파생 토픽은 허용 Competition 패킷에서 실제 제공된 필드만 보존해야 한다.

| 항목 | 판정과 결과 |
|---|---|

| 제한속도 | 전 구간 60 kph. 초과 즉시 15초, 이후 초과가 3초 지속될 때마다 15초 추가 |

| 신호 전체 실패 | 판정 대상 4개 교차로를 모두 미준수하면 해당 차시 실패 |

| 차로 | 흰색·노란색 실선/중앙선에 바퀴 1개라도 접촉·침범. 3초 지속될 때마다 5초 |
| 장애물·NPC 충돌 | 객체와 충돌할 때마다 15초. 지속 접촉은 추가 집계하지 않으나 재충돌은 추가 |
| GPS 음영 | GPS 전체 Blackout. 음영 내 차로 준수 패널티 미적용 |
| 음영 랜덤 미션 | 음영 내 임의 위치의 장애물 회피. 충돌 채점은 적용 |
| 제한 시간 | 15분 이내 완주하지 못하면 해당 차시 실패 |

주행 경로·미션 순서·체크포인트를 임의로 건너뛰면 실패다. 세부 채점 기준은
운영측 판단으로 일부 변경될 수 있다.
신호등은 판정 프로그램이 제어하며 변경 주기는 공개하지 않는다.

## 체크포인트와 순위

- 각 체크포인트 위치의 **반경 3 m 이내**를 순서대로 통과해야 한다.
- 운영 요원이 주행 불능으로 판단하고 운영 요원·팀이 승인하면 이전 체크포인트로
  복귀할 수 있다. 사용 시 15초 패널티다.
- 주행 불능 기준은 네 바퀴가 주행 영역을 완전히 벗어난 경우(GPS 음영 예외),
  주변 지형지물·장애물 충돌로 주행 불가, 체크포인트 불연속 통과다.
- 시뮬레이터 종료 등의 HW/SW 이슈는 운영 요원 판단으로 해당 차시 무효·재주행할 수 있다.
- 완주 팀은 2회 중 더 짧은 **실제 주행 시간 + 패널티 시간**으로 순위를 정한다.
- 미완주 팀은 2회 중 체크포인트 달성도, 총 주행 시간 순으로 판단한다.
- 완주 팀이 미완주 팀보다 우선한다.

GPS 음영의 차로 채점 예외는 충돌·경로·미션 순서 전체의 면제가 아니다.
예외적인 주행 불능·순위 판정은 운영측 판단을 따른다.

충돌·차로·속도 패널티 등 v1.0에도 있던 항목을 새 v1.2 기능으로 기록하지 않는다.
2026년 4월 HWP 요약의 Ubuntu/ROS 강제, LiDAR 2대·HDL32, 멀티플레이·점수 배점은
현재 주행 규정 대신 사용할 수 없다.

## 팀 제출 전 확인 사항

아래는 규정 자체가 아니라 현재 저장소를 대회용으로 준비하기 위한 확인 목록이다.
이번 문서화로 코드·실행 파라미터·센서 JSON을 변경하지 않았다.

- [ ] 개발용 `od_gt`, Ego GT pose·GT 신호·Object Info 입력을 대회 실행에서 제거한다.
- [ ] Validator의 ScenarioLoad·실험 서비스와 본선 실행을 분리한다. 본선의 장면은
  운영 요원이 로드하며 개발용 자동 시나리오 주입을 본선 허용 입력으로 간주하지 않는다.
- [ ] Localization의 `/Ego_topic` 초기 위치 의존을 제거한다. 현재 개발 기본값과
  `initial_position_source:=official_start` 선택은
  [측위 CURRENT](../localization/COMPETITION_LOCALIZATION_CURRENT_STATE.md)를 따른다.
  공식 START·heading·GNSS 정합과 checkpoint 복귀는 대회 LAN에서 별도로 검증한다.
- [ ] 실제 로드할 Network JSON의 채널을 허용 7개와 대조한다.
  `ego_network_competition_lan.json`이라는 이름만으로 대회 제출 적합성을 보장하지 않는다.
  현재 개발용 JSON에는 Ego/Object/GT 신호 등 채널이 있으므로 제출본을 별도 감사한다.
- [ ] Sensor JSON의 고정 카메라 외참·해상도·30 Hz, GPS 30 Hz, IMU 50 Hz,
  VLP16 개수·15 Hz 상한과 실제 Client 부하를 확인한다.
- [ ] 실행 인자·환경·가중치·launch를 PC 제출 전에 확정하고, 실행 이후 조작 없이
  출발·정지·checkpoint 복귀가 가능한지 확인한다.
- [ ] 2회 주행을 현장 Q/R·prior·threshold 변경 실험으로 사용하지 않는다.
  초기화·모델·센서·측위 프로파일은 제출 전에 확정한다.
- [ ] GPS 음영에서 정지·회피·재출발, GNSS 재획득, 허용 상태 입력만으로 동작하는지 확인한다.
