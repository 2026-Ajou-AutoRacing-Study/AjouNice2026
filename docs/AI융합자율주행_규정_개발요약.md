## 3. 참가팀 구성 관련 필수 규정

### 3.1 참가자격

- 대회 시작일 기준 국내 대학(교)에 재학 중인 **학부생**만 참가 가능.
- 대회 시작일까지 재학 상태를 유지해야 함.
  - 일반휴학, 군 입영 휴학, 정학, 퇴학 등으로 재학 상태를 유지하지 못하면 참가 제한.
- 최종 참가팀의 지도교수와 팀원 전원은 팀장/팀원 변경 마감 전까지 `(사)한국자동차모빌리티안전학회` 회원 가입 및 연회비 납부 필요.

### 3.2 팀 구성

- 팀원은 팀장을 포함하여 **최대 8명**.
- 각 대학은 부문별 최대 4팀까지 참가 가능.
- 1명의 지도교수가 지도할 수 있는 팀은 최대 2팀.
- 팀원 변경은 대회 시작일 기준 한 달 전까지 가능.
- 팀장 변경은 대회 시작일 기준 한 달 전까지 가능하며, **1회만 허용**.

### 3.3 지도교수

- 각 팀은 최대 2인의 지도교수로부터 지도를 받을 수 있음.
- 지도교수는 참가팀 소속 학교의 전임교원이어야 함.
- 지도교수는 알고리즘 개발을 지도할 수 있으나, **자율주행 알고리즘 제작에 직접 참여할 수 없음**.
- 지도교수는 대회 기간 중 참석해야 함.
  - 불가피하게 참석이 어려운 경우 조교 이상의 위임자를 선정하고, 지도교수 위임장을 제출해 조직위원회 사전 승인 필요.

## 4. 개발환경 규정

### 4.1 참가팀 PC

| 항목 | 필수 조건 |
|---|---|
| PC 형태 | 데스크톱 PC만 허용 |
| OS | Ubuntu 20.04 |
| ROS | ROS1 Noetic |
| OS 설치 형태 | 로컬 환경 세팅 |
| VM | VMware, VirtualBox 사용법 지원 불가 |
| 실행 프로그램 | 자율주행 알고리즘, 필요 시 rosbridge |
| 대회 당일 제공 | 대회용 판정 프로그램. 사전에는 네트워크 확인용 연습 프로그램 제공 |

### 4.2 PC 제출 및 수정 제한

- PC 제출 후 코드 등 어떠한 수정 작업도 불가.
- 예외: 환경 세팅 관련 사항.
- PC 제출이 안내된 시간보다 늦으면 **미션별 점수에서 30점 추가 감점**.
- 자율주행 코드 실행 이후 Operator는 PC를 조작할 수 없음.

### 4.3 주변기기 및 출력 포트

- 대회 당일 휴대용 모니터, HDMI to HDMI mini 케이블은 제공.
- 참가팀 PC 외장 그래픽카드에 **HDMI 출력 포트 2개**가 반드시 포함되어야 함.
- 출력 포트가 부족하면 팀에서 허브 또는 젠더를 준비해야 함.

### 4.4 성능 및 데이터 지연

- 네트워크가 모두 연결된 상태에서 다음 항목의 주기를 반드시 확인해야 함.
  - 시뮬레이터에서 설정한 데이터 전송 주기
  - rosbridge에서 수신하는 데이터 주기
- 데이터가 지연되면 PC 사양 문제로 원활한 주행이 불가능할 수 있음.
- 팀별 PC 사양에 따른 네트워크 및 센서 데이터 지연은 대회 운영 측에서 고려하지 않음.

## 6. 경기 진행 환경

### 6.1 전체 구조

대회는 다음과 같은 네트워크 구조로 진행된다.

```text
Server PC  <->  Client PC  <->  참가팀 PC
             Ethernet / Switching Hub / LAN-to-LAN
```

### 6.2 PC별 역할

| 구분 | 역할 |
|---|---|
| Server PC | 시뮬레이터 구동, 멀티플레이 구동, 동역학 처리, 제어 입력 처리 |
| Client PC | 시뮬레이터 구동, 판정 프로그램 실행 |
| 참가팀 PC | 자율주행 알고리즘 실행, rosbridge 실행 가능 |

### 6.3 멀티플레이 진행 방식

- 1번팀부터 4번팀은 멀티플레이 환경을 세팅.
- 세팅 완료 후 동시에 주행 시작.
- 참가 팀 간 충돌은 발생하지 않음.
- 각 팀은 동일한 시나리오에서 진행하지만, 자신의 시나리오가 타 팀에게 영향을 주지 않음.
- 대회용 화면 송출로 인한 성능 저하를 감안하여 개발해야 함.
- 경기 진행 환경은 주최 측 사정으로 일부 변경될 수 있음.

## 7. 경기 진행 절차

| 순서 | 단계 | 내용 |
|---:|---|---|
| 1 | Operator 입장 | 팀 대표 1명이 PC를 수령하여 세팅 |
| 2 | 준비 파일 세팅 | 운영 요원이 참가팀 PC에 준비 파일 세팅 |
| 3 | 미션 시나리오 세팅 | 운영 요원이 미션 시나리오를 Load |
| 4 | 팀별 주행 준비 | Operator가 ros_bridge 실행 및 알고리즘 실행 준비 |
| 5 | 센서 및 네트워크 세팅 | 운영 요원이 센서 세팅 파일 Load 및 네트워크 연결 |
| 6 | 네트워크 연결 확인 | 운영 요원과 Operator가 센서·차량 네트워크 연결 확인 |
| 7 | Keyboard 모드 | 운영 요원이 Ego 차량을 keyboard 모드 및 P 기어로 설정 |
| 8 | 자율주행 코드 실행 | Operator가 자율주행 코드 실행. 이후 PC 조작 불가 |
| 9 | 판정 프로그램 준비 | 운영 요원이 네트워크 연결 확인 후 판정 프로그램 준비 |
| 10 | 판정 프로그램 실행 | 운영 요원이 판정 프로그램 Reset 후 시작 |
| 11 | ExternalCtrl 모드 | 제어 모드와 기어는 Server PC에 의해 자동 변경 |
| 12 | 주행 도중 이슈 | 주행 불능 판단 시 10초 이후 마지막 체크포인트 복귀 기회 부여 |
| 13 | 주행 종료 | 운영 요원이 판정 프로그램 점수 저장 |
| 14 | 다음 주행 준비 | 다음 차시 준비. 3번부터 다시 진행 |

## 8. 주행 기회 및 주행 불능 처리

### 8.1 주행 기회

- 미션별 주행 기회는 **2회**.
- 참가팀 수에 따라 변경 가능.
- 점수는 판정 프로그램에 의해 산정.

### 8.2 주행 불능 판단 기준

운영 요원이 주행 불능으로 판단하면, 10초 이후 마지막 체크포인트로 돌아갈 수 있는 기회가 주어진다.

주행 불능 기준은 다음과 같다.

1. 차량의 바퀴 4개가 중앙선, 실선 등 주행 영역을 벗어나거나 주어진 경로를 이탈한 경우.
2. 차량이 가로등, 건물 등 주변 지형지물 또는 정적 장애물과 충돌하여 경로 복귀가 불가능한 경우.
3. 체크포인트를 불연속적으로 통과한 경우.
   - 예: 체크포인트 1을 통과한 뒤 2를 통과하지 않고 3을 통과하는 경우.

### 8.3 체크포인트 복귀 및 다음 체크포인트 이동

- 주행 불능 조건 위반 시 차량이 강제로 멈추는 로직이 적용됨.
- 마지막 체크포인트로 복귀하면 강제 정지 로직이 해제됨.
- 동일 체크포인트로 3회 돌아갔으나 더 이상 진행이 불가능하면 다음 체크포인트로 넘어가는 기회가 부여됨.
- 다음 체크포인트로 넘어가는 기회를 받은 팀은 완주하더라도, 그렇지 않은 팀과 별도로 구분하여 순위를 책정함.

### 8.4 하드웨어/소프트웨어 이슈

- 주행 중 시뮬레이터 종료 등 하드웨어 또는 소프트웨어 이슈가 발생하면, 운영 요원 판단하에 해당 차시는 무효 처리 후 재주행 가능.
- 예외 상황은 현장에서 판단.

## 10. 사용 가능 센서

> 아래에 명시된 센서 외의 센서를 사용하면 실격 사유가 될 수 있다.

| 센서 | 개수 제한 | 세부 조건 | 네트워크 |
|---|---:|---|---|
| GPS | 최대 1대 | Data Rate 자유 | UDP 또는 ROS |
| IMU | 최대 1대 | Data Rate 자유 | UDP 또는 ROS |
| 3D LiDAR | 최대 2대 | Intensity type: Intensity / 사용 가능 모델: VLP16, HDL32 / Rotation Rate 자유 | UDP 또는 ROS |
| Camera | 미션별 안내 예정 | 해상도 자유 / Frame Rate 자유 | UDP 또는 ROS |

### 10.1 3D LiDAR 주의 사항

- ROS로 LiDAR를 사용할 경우 `ROS-Velodyne` 드라이버 설치 후 launch 파일을 실행해야 함.
- 사용 가능 모델은 `VLP16`, `HDL32`.

### 10.2 Camera 주의 사항

- 카메라 개수는 미션별로 추후 안내 예정.
- 해상도와 Frame Rate는 자유.
- Pitch angle은 ±30° 이내.

| `[UDP or ROS] GPS` | GPS 센서 데이터 | 최대 1대 |
| `[UDP or ROS] IMU` | IMU 센서 데이터 | 최대 1대 |
| `[UDP or ROS] Camera` | Camera 센서 데이터 | 미션별 개수 안내 예정 |
| `[UDP or ROS] 3D LiDAR` | 3D LiDAR 센서 데이터 | ROS 사용 시 ROS-Velodyne 드라이버 필요 |

### 12.1 제어 명령 관련 주의 사항

- `/Ctrl_cmd` 제어 시 `longi type 1`을 사용한다.
- `longi type 1`은 `accel`, `brake` 제어 방식이다.

## 16. 감점, 경고, 실격 조건

### 16.1 감점

| 상황 | 감점 |
|---|---:|
| 기술세미나 불참 | 3점 |
| 부적절한 이의 제기 | 해당 경기 3점 |
| PC 제출 지연 | 미션별 30점 추가 감점 |
| 기술보고서 지연 제출 | 원문상 1일 5점 감점이라고 하나 예시와 불일치. 확인 필요 |
| 전년도 수상팀 알고리즘 차별성 부족 | 최대 10점 벌점 가능 |

### 16.2 경고

- 대회의 안전한 운영에 지장을 초래한 경우 심사위원회 결정에 따라 경고 부여.
- 경고가 부여되면 심사위원회 결정에 따라 벌점이 부과될 수 있음.
- 3회 이상의 경고를 받으면 실격 사유.

### 16.3 실격 가능 조건

다음 항목은 실격 사유가 될 수 있다.

1. 참가자 요건 위반.
2. AI융합자율주행 부문 운영규정의 주요 규정 위반.
3. 경기규정상 실격 사유 위반.
4. 3회 이상의 경고.
5. 대회 규정 또는 대회 취지를 심각하게 위반했다고 조직위원회가 판단한 경우.
6. 기술보고서 미제출.
7. 전년도 참가팀 중 사전 공지 없이 대회 당일 미참가한 팀이 소속된 학교의 참가팀.
8. 규정 2.5의 시뮬레이터 환경 차량 및 센서에서 제시한 센서·네트워크 외의 센서·네트워크 사용.
9. 제출 코드의 코드 유사성이 현저히 높다고 심사위원회가 판단한 경우.

## 17. 이의 제기 규정

- 해당 팀에 부당한 판정이 있는 경우, 지도교수 또는 팀장이 판정 후 30분 이내에 서면으로 이의 제기 가능.
- 다른 팀에 대한 이의 제기는 불가.
- 이의 제기 결과는 서면으로 통보.
- 부적절한 이의 제기라고 판단되면 해당 경기에서 3점 감점.
- 기술세미나 불참 팀은 대회 운영 및 결과에 대해 이의를 제기할 수 없음.
- 홈페이지의 `자주하는 질의응답` 코너 답변은 규정과 동일한 효력을 가짐.

## 19. 원문상 확인 필요한 애매한 부분

아래 항목은 원문에 불명확하거나 추후 공지로 남겨진 부분이다. 팀 내부 문서에는 `확인 필요`로 관리하는 것이 좋다.

1. **기술보고서 지연 감점**
   - 원문: `1일 지연에 5점 감점`.
   - 예시: 9월 25일 마감인데 9월 26일 제출 시 `15점 감점`.
   - 두 내용이 불일치하므로 공식 질의 필요.

2. **카메라 개수**
   - 원문: `미션 별 안내 예정(추후 공지)`.
   - 현재 문서만으로는 최종 카메라 개수를 확정할 수 없음.

3. **상세 배점 항목**
   - 원문: 미션 공개와 동시에 공개.
   - 현재 문서에는 자율주행 700점 / AI 300점 비율만 명시.

4. **경기 환경 변경 가능성**
   - Server/Client/참가팀 PC 구조 및 멀티플레이 환경은 주최 측 사정으로 일부 변경 가능.

5. **문서 내 장 번호 참조 불일치**
   - 실격/벌점 항목에서 `제4장 경기규정`, `3.4 벌점규정`을 참조하지만, 제공된 문서 본문은 제2장 이후 양식으로 이어짐.
   - 별도 공지 또는 추가 규정 문서가 있는지 확인 필요.
