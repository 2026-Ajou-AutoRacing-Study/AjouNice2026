# no_lamps 단발 공백 완충 — 2026-10-27

## 결정

**후속 변경:** 아래 최초 시험의 '황색 제외'는 현재 기준이 아니다. 사용자 요청으로 황색도
포함하고, 같은 정상 지도 연결의 `low_confidence_bits:*`와 `no_lamps`를 공유0.2초 기한으로
처리한다. 정차 중 R도 포함한다. 단 확실히 켜진 새 램프가 이전 조합에 없으면 이전 색으로
덮지 않는다. 실제 새 정상 색·identity 상실·만료 처리는 즉시 반영한다. 원본 시각과 황색
잔여시간을 갱신하지 않는다. 아래 최초 no_lamps 단독 결과는 당시 근거로 보존한다.

전체 색에 7프레임/4표를 다시 적용하지 않고 **같은 신호등의 no_lamps만 최대0.2초 완충**한다.
신호 전체 다수결은 실제 R/Y 전환도 과거 G 표에 눌릴 수 있다. 이번 방식은 새 R/Y가
판독되면 즉시 교체하고, CNN이 모든 램프를 못 읽은 짧은 공백에만 이전 관측을 전달한다.
가중치·신호 허가 조합·황색 통과·planner 정책은 바꾸지 않았다.

## 적용 조건과 종료

- 현재 시각의 정상 map-association, 같은 미션·같은 head·현재 유효 ROI가 모두 필요하다.
- CNN known=true, reason=no_lamps, 실제 4-bit가 모두0인 경우만 해당한다.
- 이전 램프에 황색이 있으면 유지하지 않는다. 이전 R은 R, G는 G, R+좌화살표는 그대로다.
- 마지막 실제 관측 처리 시각부터0.2초, 그 관측 원본 source age0.3초 이내를 동시에 요구한다.
- hold 중에는 원본 stamp·시계를 갱신하지 않는다. 연속 no_lamps로 기한을 연장하지 못한다.
- 첫 판독 이전·다른 head·미션 변경·실제 화각/지도 연결 실패에는 적용하지 않는다.
- 실제 새로운 R/Y는 첫 프레임 전달한다. 지속 소등은 만료 뒤 UNKNOWN이며 캐시를 지운다.
- 실제 소등인지 일시 판독 실패인지는 이 조건만으로 확정할 수 없다. **실제 소등 직후에는
  이전 GO가 최대0.2초 유지될 수 있다.** 무위험 처리나 인식 정확도 향상으로 표현하지 않는다.

launch `no_lamps_hold_sec` 기본0.2, 명시적0으로 복귀한다. Python 정책 API 기본0은 유지한다.

## 후속: 황색 포함·soft/no_lamps 공통 기한

2026-10-27 사용자 요청으로 황색 제외를 제거했다. 새 플래그를 추가하지 않고 기존
`no_lamps_hold_sec=0.2`를 같은 정상 지도 head의 soft/no_lamps 공백에 공유한다.
기존 특수 이동 저확신 fallback은 이 공유 경로가 적용되는 프레임의 만료를 우회하지 못한다.
0을 명시하면 새 공유 경로가 꺼지고 기존 저확신 계약은 유지된다.

정차 중 R→low-confidence→no_lamps도 첫 공백에서 캐시를 지우지 않으며, 원래 관측의
처리 시각·원본 stamp부터 만료한다. 확실히 켜진 새 R/Y/좌화살표 등이 이전 조합에 없으면
이전 허가로 덮지 않는다. 시간·미션·head·지도 연결의 기존 보호는 유지한다.

패키지 테스트362개 통과. 실제 C++ `Guard`/`timedYellowDecision` 헤더를 컴파일해
held Y의 원본 stamp 재전달이 황색 시작 시각을 갱신하지 않고, 잔여시간이 계속 줄며,
OFF/예산 만료/새 적색에서 통과 허가를 만들지 않는 것을 확인했다. planning 코드는 수정하지 않았다.
