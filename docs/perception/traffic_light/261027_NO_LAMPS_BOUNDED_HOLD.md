# no_lamps 단발 공백 완충 — 2026-10-27

## 결정

전체 색에 7프레임/4표를 다시 적용하지 않고 **같은 신호등의 no_lamps만 최대0.2초 완충**한다.
신호 전체 다수결은 실제 R/Y 전환도 과거 G 표에 눌릴 수 있다. 이번 방식은 새 R/Y가
판독되면 즉시 교체하고, CNN이 모든 램프를 못 읽은 짧은 공백에만 이전 관측을 전달한다.
가중치·신호 허가 조합·황색 통과·planner 정책은 바꾸지 않았다.

## 적용 조건과 종료

- 현재 시각의 정상 map-association, 같은 미션·같은 head·현재 유효 ROI가 모두 필요하다.
- CNN known=true, reason=no_lamps, 실제 4-bit가 모두0인 경우만 해당한다.
- 이전 램프에 황색이 있으면 유지하지 않는다. 이전 R은 R, G는 G, R+좌화살표는 그대로다.
- 마지막 실제 관측 처리 시각부터0.2초, 그 관측 원본 source age0.3초 이내를 동시에 요구한다.
- hold 중에는 원본 stamp·시계를 갱신하지 않는다. 연속 no_lamps로 기한을 연장하지 못한다.
- 첫 판독 이전·다른 head·미션 변경·실제 화각/지도 연결 실패에는 적용하지 않는다.
- 실제 새로운 R/Y는 첫 프레임 전달한다. 지속 소등은 만료 뒤 UNKNOWN이며 캐시를 지운다.
- 실제 소등인지 일시 판독 실패인지는 이 조건만으로 확정할 수 없다. **실제 소등 직후에는
  이전 GO가 최대0.2초 유지될 수 있다.** 무위험 처리나 인식 정확도 향상으로 표현하지 않는다.

launch `no_lamps_hold_sec` 기본0.2, 명시적0으로 복귀한다. Python 정책 API 기본0은 유지한다.
현재 source/설치본/팀 PC는 따로 확인해야 하며 git 변경만으로 다른 PC가 갱신되지 않는다.

## 재현·전환 시험

도구 `scripts/evaluation/audit_traffic_light_no_lamps_window.py`는 closed bag의 debug 관측열만
읽고 ROS 송신·GPU 추론·원본 수정을 하지 않는다. callback 입력은 이미 검증된 선택 ROI를
재구성하고, bag 입력은 원본 map_rois를 사용한다. tuple 정책 재생이며 confidence 완전 재현은 아니다.

합성10Hz의 충분한 G 이력 뒤 R/Y 입력에서 7/4 투표는3프레임(0.3초), 3/2 투표는
1프레임(0.1초) 뒤 새 색으로 바뀐다. 새 후보는 no_lamps 뒤의 실제 R/Y도 첫 프레임 전달한다.
이는 **제어된 합성 입력의 정책 지연**이지 실제 카메라·CNN·제동 총 지연 측정은 아니다.

실제 노드 callback 테스트에서 A/B/C/D 허가 보존·원본 stamp·시간 만료·지속 소등·
즉시 R/Y 전환·head/미션/지도 변경·flag0·황색 미유지를 확인한다.
저장 bag 실험만으로 planner/제어 폐루프의 움찔이 없어졌다고 주장하지 않는다.

패키지 Python 테스트353개 및 perception 문서 계약 검사는 통과했다.
로컬 설치기를 실행해 GPU 모델 추론·ROS import·소스/설치 Python·launch 일치를 확인했다.
