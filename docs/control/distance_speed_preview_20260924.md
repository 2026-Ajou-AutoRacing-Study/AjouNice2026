# 종제어기 거리 기반 속도 preview 변경

## 적용

longi_pi_autoware의 전방 최소 속도 즉시 추종을 거리 기반 감속 envelope로 변경했다. 현재 위치의 계획 속도가 기본 목표다. 전방 각 제한 속도 vf, 해당 위치까지 경로 거리 d에 대해 아래 허용 속도를 구해 기본 목표를 제한한다.

- 접근 속도 va = max(현재 속도 절댓값, 현재 위치 계획 속도)
- 가용 거리 = max(0, d - va × 응답 지연 - 거리 여유)
- 현재 허용 속도 = sqrt(vf² + 2 × 설정 감속도 × 가용 거리)

매번 현재 상태와 새 궤적으로 다시 계산한다. 종제어기 PI 계수와 정규화된 MORAI 액추에이터 출력 방식은 유지했다. 최적화 성공/실패 여부를 입력으로 감속을 추가하지 않는다. 기존 경로를 최신 장면이 무효화한 경우의 PO/검증기 정지점 생성 로직 자체를 이번에 제거하지는 않았다.

## 설정

- speed_preview/deceleration_mps2: 2.0
- speed_preview/response_delay_s: 0.3
- speed_preview/distance_margin_m: 0.2

이 값은 시험용 계산 가정이며 측정된 MORAI 최대 감속도/지연 보증이 아니다. 현재 가속도 상태를 포함한 jerk 제약 해석기는 이번 변경에 포함하지 않는다. 급히 새로운 정지점이 생겨 가용 거리가 부족하면 목표/제동이 크게 변할 수 있다.

현재 위치와 최근접 경로점 사이 진행 방향 투영 거리를 반영한다. 전방 검사는 기존 5~30m 기준보다 필요한 정지거리가 길면 그 거리까지 확장하고, 성긴 구간에서는 검사 범위를 처음 넘는 점도 확인한다. 후진 및 preview 비활성 동작은 기존과 동일하게 현재 위치 계획 속도를 사용한다. 현재 위치의 0 속도, 상태/입력 무효 정지 조건은 유지된다.

## 검증

- Release 설정의 기존 패키지 빌드 및 install_aw149 설치 완료.
- 단위 시험 6개 통과: 먼 정지, 가까운 정지, 응답 지연 거리, 제한 위치의 목표, 거리 증가에 따른 허용값, 고속 정지거리 검사 범위.
- private ROS master 11476에서 설치된 실제 longi_pi_autoware 실행. 6개 입력 시험 통과. 입력→목표→명령 연결을 보기 위해 이 시험에 한해 ki=0으로 설정했다. 배포 ki=0.05는 변경하지 않았다.
  - 5km/h, 5m 앞 정지: brake=0.
  - 5km/h, 0.4m 앞 정지: brake=1.
  - 가까운 정지 요구 해제 후: brake=0.
  - 5m/s, 8m 앞 3m/s 제한: brake=0.
  - 30km/h, 10m 앞 정지: brake=1.
  - 현재 속도와 현재 계획 속도 모두 0: hold brake=0.2.
- 183125 백 최종 궤적 307개의 기록된 공간 속도 프로파일에 같은 C++ helper를 적용해 기존 방식과 비교했다.
  - 현재 목표 0: 기존 23개 → 변경 0개.
  - 목표가 0.5km/h 이상 증가: 148개.
  - 현재 위치 계획 속도 초과: 0개.
  - 기록된 현재 속도보다 목표가 1km/h 넘게 낮은 프레임: 16개 → 0개.

백 비교는 궤적 수신 시점의 최근접점 기준으로 이미 추출된 50m 프로파일을 사용했다. 실제 노드의 점 사이 위치 투영, 제어 타이머 버퍼 순서, PI 적분 및 차량 응답까지 재현한 폐루프 시험이 아니다. 이 결과를 제동 횟수 0 또는 정지거리 보장으로 해석하면 안 된다.

## 남은 제한

이번 변경은 이미 velocity smoother가 현재 위치에 부여한 3km/h 계획 속도를 높이지 않는다. 183125 백의 근접 곡률 변화→조향 속도 제한 문제와 PO 전방 정지점 반복의 원인 분석/개선은 별도다.

소스/설치 YAML과 실행 바이너리 갱신 완료. 실제 제어기 프로세스의 재시작이 필요하다. PO 40점·0.5m와 controller source timeout 10초 설정은 유지되는 것을 확인했다.
