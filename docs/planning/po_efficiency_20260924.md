# PO 후보 탐색 수정 및 최근 15개 백 검증

## 판정

**수정·빌드·15개 백 재생은 완료했다. 무정지 회피와 안정적인 10 Hz는 아직 미달이다.**

- 최종 출력 3,195프레임 중 장애물 장면 활성 2,132프레임. 활성 프레임의 정지 출력은 242개다.
- 188개는 기록된 차체가 관측 장애물의 하드 마진과 이미 겹쳤다. 재생은 수정 궤적을 따라 자차를 움직이지 않으므로 수정 플래너의 실제 충돌 횟수로 해석할 수 없다.
- 나머지 54개는 PO에서 먼저 0 속도가 된 48개, 최종 검증기에서 0이 된 6개다.
- 검증 범위 내 이동 궤적의 관측 장애물 침범·도로 이탈·반대 방향각은 각각 0개. 노드 크래시 및 자동 검사 오류도 0개.
- 자동 PASS에는 무정지 및 100 ms 발행 주기 요구가 포함되지 않는다. PASS를 회피 성공으로 사용하지 않는다.

## 적용한 변경

1. 장애물 옆에서 반대편 후보가 측정된 현재 상태와 연결될 수 없는 명확한 경우, 스플라인·경계·QP 구성 전에 제외한다. 진입/이탈 및 기준축이 크게 다른 회전은 기존 도달 가능성 검사를 수행한다.
2. 이전 경로가 현재 위치·방향과 충분히 맞을 때 이전 공간 경로를 우선 seed로 사용한다. 어긋나면 도로 기준 경로부터 다시 최적화하고 이전 seed를 재시도한다. 이전 seed 확장은 콜백당 한 번 수행한다.
3. 이전 경로를 현재 장면·도로·충돌·곡률·길이 조건으로 재검증한다. 정렬된 유효 경로가 있을 때 재시도 예산을 최대 70 ms로 제한한다. 단일 solver 호출 자체의 실행시간 상한은 아니다.
4. 선호하는 연속 경로에서 검증된 새 해가 나오면 새 결과를 채택하고 나머지 방향 탐색을 끝낸다. 복구 탐색은 유지한다. 매 주기 최적화하며 이전 방향을 강제로 고정하지 않는다.
5. 도로 검사를 seed 수용 조건에 포함해 도로 밖 seed 때문에 다른 seed 재시도가 누락되지 않도록 했다.
6. OSQP warm start 호환성을 행렬 크기뿐 아니라 P/A의 CSC 행 인덱스·열 포인터까지 확인한다. 값만 갱신하는 API에 구조가 다른 희소행렬을 전달할 수 있던 오류를 수정했다. 이것이 모든 과거 실패의 원인이라는 뜻은 아니다.

BPP/SOA 인터페이스는 이번에 바꾸지 않았다. BPP 기준 경로·도로 경계와 별도 장애물 장면을 PO가 사용하며 SOA는 optimization_base이다. 기준 경로가 존재하는 것과 shift-line 회피 사용은 서로 다르다.

## 검증 방법

- 최근 장애물 회피 기록 15개, 길이 약 9.6~38.7초. 최신 회피·복귀 기록을 포함하기 위해 약 20초를 넘는 짧은 기록도 포함했다. 한 바퀴 기록은 제외했다.
- private ROS master 11475, 백마다 새 프로세스, native rosbag player 1배속, 5초 초기화. BPP→BVP→EB→PO→MVP→VS→최종 검증기 전체 재생.
- 기록된 자차 상태를 입력한 재생이며 폐루프 주행 성공 검증이 아니다. 검사 대상은 관측 envelope와 hard margin이며 GT 충돌 검사와 동일하지 않다.
- 최종 출력은 sequence/CRC로 실제 검사 장면에 연결했다. 정지는 장애물 활성 프레임의 현재 위치 목표 속도 0.01 m/s 미만이다.
- PO 처리시간은 초기화 측정도 포함한다. 발행 간격과 정지 통계는 백 시작 이후다. PC의 다른 작업 부하가 있어 엄격히 통제한 성능 벤치마크는 아니다.
- Release 빌드·설치 완료. 장애물/초기 상태 검사 15개 + 제약/희소행렬 검사 5개 = 단위 테스트 20개 통과. git diff --check 통과.

## 남은 실패

- **20260924_072758**: 경로 header 기준 약 15.008~15.903초, 최종 수신 기준 약 15.230~16.419초에 정지 10프레임. 당시 차체는 관측 하드 마진과 겹치지 않았다. 최초 0 출력은 PO이며 최종 검증기 실패는 0개다. 인접 로그는 새 최적화 실패와 이전 경로 유지 실패를 기록했다. 로그가 throttle되므로 후보별 정확한 탈락 사유를 이 로그만으로 확정할 수 없다.
- 이 백은 직전 후보 v6 재생에서는 정지 0개였지만 v7에서는 10개가 나타났다. 반복 및 후보별 진단 없이 차이를 CSC 수정 하나의 효과로 단정하지 않는다. **무정지 회귀 요구는 미통과로 남긴다.** 잘못된 행렬 재사용으로 되돌려 통과시키지 않았다.
- 비중첩 정지 중 PO 48개는 후보별 QP 상태, 후처리 곡률/도로/충돌 검사, 이전 경로 탈락 사유를 구분하는 추가 진단이 필요하다. 현재 자료는 최초 정지 발생 단계를 확인한 것이며 모든 프레임의 근본 원인을 확정한 것은 아니다.
- 검증기에서 먼저 0이 된 6개는 별도 단계로 분리했다. 전체 검증 실패 필드는 lateral jerk 8, longitudinal min acc 12, relative angle 2, trajectory shift 88이다. 정지 프레임 수와 일대일 대응하지 않는다.
- 10 Hz를 위해 남은 긴 콜백의 전처리·QP 구성·solve·후처리 시간을 분리하고, 구조가 고정된 희소행렬 조립과 복구 탐색 예산을 검토해야 한다. 현재 변경으로 시간 상한을 보장하지 않는다.
