# 정지한 최적화 실패의 회복 모드

현재 구현은 Path Optimizer(PO)의 상태와 출력 궤적의 출처를 구분한다.

- 진입: 정상 최적화가 실패하여 PO가 정지 출력을 선택하는 상태가 2초 이상,
  실제 속도 절댓값이 1 km/h 이하인 상태가 2초 이상 지속되고 실패 주기가
  최소 5회 누적되어야 한다. 중간 정상 출력, 입력 단절, 시각 역행, 의도적
  정지는 진입 근거를 끊는다. 개별 후보의 QP 실패를 누적하지 않는다.
- 허용 맥락: 신선한 경로·동기 정적 장면·측위·예측 객체, 자율 운전 상태,
  MORAI AV-ExternalCtrl(2)·D(4), 행동/객체 정지 요청 부재가 필요하다.
  유효한 빈 정적 장면은 허용하지만 장면 누락은 허용하지 않는다.
- 활성 상태: 정상 경계 최적화를 매 주기 먼저 시도한다. 정상 경계 내에서
  새로 풀린 궤적의 연결·차체·정적/동적 충돌·곡률 검사가 통과하면 즉시
  정상 궤적을 선택하고 모드를 해제한다. 이전 궤적 재사용은 복귀 근거가 아니다.
- 정상 해가 없으면 같은 탐색 예산 안에서 도로 경계의 hard 조건만 완화한다.
  정상 solve가 탐색 예산을 초과해도 회복 solve 1회는 보장한다. 추가 후보는
  남은 예산 안에서 탐색한다. 장애물 충돌 및 차량 제약은 유지한다. 안전 후보가 없으면 정지하고 다음
  주기에 재시도한다. 시간·횟수·주행 속도에 따른 모드 해제는 없다.
- 회복 전용 속도 상한은 없다. 입력 정지점과 기존 속도·가감속·jerk 정책을
  유지한다. 입력/정지 맥락이 불허 상태가 되면 회복 주행을 보류한다.
  안전한 새 정상 해가 없는 한 모드는 유지하며, 진입 조건이 해제되어도 정상 복귀 검사는 계속한다.

`Trajectory.boundary_recovery`는 그 메시지의 경계 완화 출처다. MVP는 이
표시가 있는 궤적에만 BoundaryDeparturePrevention의 경계 제동을 생략하며,
객체·교통 관련 플러그인은 계속 실행한다. Velocity Smoother가 표시를 전달하고
최종 Planning Validator가 평활화된 속도를 사용하여 다시 충돌 검사한다.
정적 장애물의 기존 접촉 탈출 예외는 경계 회복 궤적에 적용하지 않는다.

동적 검사는 예측 시각을 보정하고 제공된 모든 예측 분기를 시간별 차체
swept footprint로 검사한다. 예측 종료 후에는 끝 자세를 유지한다. 근처의
움직이는 객체에 예측이 없거나 입력이 오래되면 회복 출력을 정지시킨다.
검사는 입력 예측에 대한 검사이며 실제 주행 검증을 대신하지 않는다.

관측 토픽은 `/planning/recovery/status`, `/planning/recovery/behavior_stop`,
`/planning/recovery/external_stop`이다. 정상/회복 최적화의 고정 prefix를
공유하지 않으며, 최적화 이력 초기화는 회복 상태나 실패 누적을 초기화하지 않는다.

메시지 정의가 변경되므로 planning 및 base overlay와 모든 플러그인을 함께
재빌드해야 한다. 예전 `Trajectory` bag의 직접 재생에는 ROS MD5 호환 처리가
필요하다. 실행 설정은 `autoware_launch/config/ros1/.../autoware_path_optimizer/`
아래 `path_optimizer.param.yaml`의 `recovery/*`이다.
