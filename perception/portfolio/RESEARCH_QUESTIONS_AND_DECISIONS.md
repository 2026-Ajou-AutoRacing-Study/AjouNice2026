# 대회 경험에서 출발한 연구 질문과 의사결정

작성일: 2026-10-31 · 목적: 대학원 지원·면담·개인 포트폴리오 준비

이 문서는 주상우가 대회 준비 중 제기한 질문과, 팀·AI 도구와 함께 수행한 분석 및
의사결정을 연구 관점으로 정리한 회고다. 새로운 알고리즘의 독창성이나 모든 구현의
단독 기여를 주장하는 문서는 아니다. 개인의 문제 제기·판단과 공동 구현·실험의 기여는
지원서에서 구분한다. 운영 기본값은 각 분야의 CURRENT와 실제 코드에서 확인한다.

## 핵심 소개

> 카메라–LiDAR 인지 시스템을 데이터 구축부터 학습·실시간 배포·주행 검증까지 연결하면서,
> 정보가 부족한 조건의 성능 한계, 시간적 불안정성, 정확도와 지연의 절충을 분석했다.
> 단순히 데이터를 늘리거나 모델을 바꾸기보다 실패 조건을 분해하고, 근거가 부족한
> 개선 방향은 중단·보류하는 방식으로 제한된 개발 자원을 배분했다.

아래의 ‘후속 연구 질문’은 지원 동기를 구체화하기 위한 제안이며, 이미 달성한 성과가 아니다.

## 1. LiDAR가 0점인 초장거리 차량: 데이터를 더 모으면 해결되는가?

- **내 질문:** 현재 운영점에서 검출이 거의 안 되는 객체에 데이터를 계속 추가하는 것이
  타당한가? 해당 객체는 사실상 영상에 의존한 3D 위치 추정을 요구하는 것 아닌가?
- **확인한 근거:** 동일 native 512프레임 평가에서 전방 80~100m의 LiDAR 0점 차량
  53개는 E24·E12 모두 score 0.4·XY 오차 1m 기준 적중 0개였다. 반면 1~4점 차량의
  적중은 21/44→34/44, 5점 이상은 17/37→28/37로 개선됐다.
- **내린 결정·실행:** ‘전체 성능이 낮으니 추가 수집’으로 묶지 않고 거리·지원점 수별로
  분석했다. 이 0점 문제를 해결한다는 명목의 무작정 추가 수집·재학습은 더 밀어붙이지 않고,
  대회 준비의 다른 개선 과제로 자원을 돌렸다. 이전 데이터 확장 전체를 무의미하다고
  결론낸 것은 아니다.
- **결론의 경계:** 0/53은 특정 모델·운영 threshold·오차 기준의 결과다. 카메라만으로
  검출이 원천적으로 불가능하다거나 데이터 보강이 항상 무효하다는 증거가 아니다.
- **대학원 어필:** 데이터 규모와 정보량을 구분하고, 실패 원인을 가설로 분해한 경험.
- **후속 연구 질문:** LiDAR 지원점·거리·영상 가시성에 따른 modality 의존성을 어떻게
  측정하고, 희소·결손 조건에 맞춰 학습과 융합을 바꿀 수 있는가?
- **근거:** [동일 입력 비교, 57절](../../docs/bevfusion/evidence/261010_BASE5_INPUT_POOL_OPTIMIZATION_EVIDENCE.md#full30750-e12-bags-far-front-261023),
  [0점 진단, 58절](../../docs/bevfusion/evidence/261010_BASE5_INPUT_POOL_OPTIMIZATION_EVIDENCE.md#full30750-zero-lidar-threshold-research-261023).

## 2. 원거리 confidence threshold만 낮추면 되는 것 아닌가?

- **내 질문:** 원거리에서 낮은 점수라도 살리면 유용한 차량을 더 검출할 수 있지 않은가?
- **확인한 근거:** E12의 0점 GT 주변 후보는 존재하더라도 점수가 낮았다. 같은 subset의
  전방 전체 134 GT에서 threshold 0.4→0.1→0.05에 따라 1m 적중은 62→75→91개,
  미대응 출력은 0→18→131개로 증가했다. 이는 ROS NMS 이전 decoded 출력 진단이다.
- **내린 결정·실행:** recall 증가만 보지 않고 음성 프레임과 미대응 출력을 함께 비교했다.
  점수를 무조건 낮춰 0점 문제를 해결했다고 주장하지 않았다.
- **결론의 경계:** GT 주변 후보 선택은 GT를 아는 사후 진단이다. 온라인 검출률이 아니며,
  모델 score도 보정된 성공 확률이 아니다. 객체가 LiDAR 0점이어도 전체 모델의 다른
  LiDAR 정보가 제거된 것은 아니므로 엄밀한 camera-only 실험과 구분한다.
- **대학원 어필:** 운영점 선정, precision–recall 절충, confidence 해석에 대한 비판적 사고.
- **후속 연구 질문:** 거리·지원점별 calibration과 불확실성 기반 의사결정이 유효한가?
- **근거:** [거리별 score·음성 대조, 58절](../../docs/bevfusion/evidence/261010_BASE5_INPUT_POOL_OPTIMIZATION_EVIDENCE.md#full30750-zero-lidar-threshold-research-261023).

## 3. 평가 기준을 완화하면 모델이 좋아지는 것인가?

- **내 질문:** LET 계열 평가나 거리 허용 오차 변경은 학습 개선인가, 평가 관점의 변경인가?
  LiDAR 1점 이상 객체만 평가하면 성능이 얼마나 달라지는가?
- **내린 결정·실행:** 평가 변경과 모델 변경을 분리했다. 1점 이상 GT만 남긴 보조 평가를
  수행하되 원래 전체 GT 평가도 유지하고, 가중치·예측을 바꾸지 않은 결과로 구분했다.
- **결론:** 평가 대상이나 매칭 기준을 바꿔 점수가 상승해도 모델 능력이 향상된 것은 아니다.
  원거리의 depth 오차 특성을 이해하는 평가와, 실제 주행에 필요한 위치 정확도는 별개다.
- **결론의 경계:** LET 평가기의 운영 도입·학습 적용까지 완료했다는 주장은 하지 않는다.
- **대학원 어필:** 지표의 정의·분모·평가 대상이 결론을 어떻게 바꾸는지 검토한 경험.
- **후속 연구 질문:** 원거리 3D 오차를 반영하면서 하위 주행 위험과도 연결되는 평가는 무엇인가?
- **근거:** [전체/부분 평가 구분, 57절](../../docs/bevfusion/evidence/261010_BASE5_INPUT_POOL_OPTIMIZATION_EVIDENCE.md#full30750-e12-bags-far-front-261023),
  [LiDAR 1점 이상 보조 평가, 59절](../../docs/bevfusion/evidence/261010_BASE5_INPUT_POOL_OPTIMIZATION_EVIDENCE.md#full30750-positive-lidar-evaluation-261023).

## 4. 프레임별 검출이 정확해도 시간적으로 흔들리면 주행에는 더 나쁘지 않은가?

- **내 질문:** 높은 AP에도 객체 위치·속도·ID나 신호 판독이 순간적으로 흔들리면 판단이
  정지와 진행을 반복할 수 있지 않은가? 단일 프레임 정확도만으로 충분한가?
- **확인한 문제:** 검출 재취득 시 UUID 변경, 정지 객체의 가상 속도, 신호 판독·매칭 누락을
  서로 다른 문제로 다뤘다. 화면의 STOP 표시와 실제 제동 명령·차량 감속도 구분했다.
- **내린 결정·실행:** 연속 bag·현재 프레임·주행 영상·제어 출력을 대조하고, 원인별로
  UUID 계승, 정적 출력 pose 유지, 제한된 UNKNOWN 유예 등을 검토·적용했다.
  이들은 하나의 보편적 필터가 아니라 각기 다른 정보 경계의 처리다.
- **결론의 경계:** 모든 감속·충돌을 인지 흔들림의 탓으로 돌리지 않는다. 국소 재현 개선과
  전체 코스·새 환경의 안전성 보장은 다르며, 대회 충돌의 모듈별 원인은 별도 분석 대상이다.
- **대학원 어필:** 오프라인 정확도와 폐루프 시스템 품질 사이의 간극을 문제로 정의한 경험.
- **후속 연구 질문:** 시간적 일관성·누락 길이·ID 변화를 어떻게 평가하고 주행 품질과 연결할까?
- **근거:** [Tracking CURRENT](../../base_ws/src/perception_object_pipeline/docs/TRACKING_PREDICTION_CURRENT.md),
  [신호등 CURRENT](../../docs/perception/traffic_light/CURRENT.md).

## 5. 흔들림을 줄이는 필터가 실제 보행자의 출발 반응까지 늦추지 않는가?

- **내 질문:** 정지 객체의 가상 움직임을 억제하려고 일정 시간·연속 관측을 요구하면,
  트리거로 갑자기 출발하는 보행자 대응이 늦어지는 것 아닌가?
- **내린 결정·실행:** 추가 시간 대기를 넣는 속도 완충 후보와, 속도 진입/복귀 기준만 다른
  히스테리시스를 구분했다. PED는 동적 진입 ≥0.7m/s·정적 복귀 ≤0.2m/s,
  중간은 이전 상태 유지로 소유권을 정하고 추가 대기시간을 넣지 않는 방향을 채택했다.
  차량·UNKNOWN에 동일 보행자 기준을 무차별 적용하지 않았다.
- **결론의 경계:** ‘추가 대기시간 없음’은 센서·검출·속도 추정까지 지연 0이라는 뜻이 아니다.
  새 객체가 중간 속도로만 움직이면 초기 정적 상태가 유지될 수 있다. 대회 보행 속도 가정은
  실세계 보행자 전체에 대한 보장이 아니며 느린 출발은 남은 한계다.
- **대학원 어필:** 안정성과 반응성의 상충을 인식하고, 상태 전이와 수치 필터를 구분한 경험.
- **후속 연구 질문:** false motion 억제와 true motion onset 지연을 함께 최소화할 수 있는가?
- **근거:** [보행자 소유권·완충 후보 및 한계](../../base_ws/src/perception_object_pipeline/docs/TRACKING_PREDICTION_CURRENT.md).

## 6. 같은 객체의 ID 유지와 동시에 두 박스로 검출되는 문제는 같은가?

- **내 질문:** UUID 연속성을 개선하면 중복 박스도 해결되는가? NMS·병합 거리를 크게
  늘려서 해결하는 것은 가까운 실제 두 객체를 지우는 도박 아닌가?
- **내린 결정·실행:** 시간적으로 끊긴 정지 객체의 유일한 재검출에는 출력 UUID 계승을
  적용했다. 동시 두 박스는 별도의 association·birth·검출 중복 문제로 남겨 구분했다.
  소형 억제 후보는 효과 범위와 오병합 위험을 검토한 뒤 기본 OFF로 남겼다.
- **결론의 경계:** UUID 계승은 박스 삭제·병합이나 EKF 상태 계승이 아니며 모든 큰 상자
  분리를 해결하지 않는다. 억제 후보가 일부 실패 장면을 바꿔도 발동 여부 없이 인과를 주장하지 않는다.
- **대학원 어필:** 겉보기 증상이 비슷한 실패를 메커니즘별로 분리하고 부작용을 검토한 경험.
- **후속 연구 질문:** 시간·형상·센서 지지 정보를 사용해 실제 근접 객체와 중복 검출을 구분할까?
- **근거:** [UUID·중복 birth·소형 후보](../../base_ws/src/perception_object_pipeline/docs/TRACKING_PREDICTION_CURRENT.md).

## 7. 모든 부분을 TensorRT/CUDA로 바꾸는 것이 최선인가?

- **내 질문:** 재학습 없이 어느 부분을 바꾸면 정확도 손실 대비 속도 이득이 가장 큰가?
  수치가 완전히 같지 않다는 이유만으로 실용적인 최적화를 거부해야 하는가?
- **확인한 근거:** camera backbone·neck의 FP16 TRT로 서비스 평균 74.55→64.59ms
  (약13.4% 감소). 같은 전체 validation 4,614프레임 mAP는 94.0545→94.0661%였다.
  추가 SDPA·좌표 cache는 전체 mAP 94.066058→94.065589%였고, 별도 연속480프레임
  서비스 비교에서 65.97→60.34ms였다. 비교 표본·실행 범위가 다른 수치는 합산하지 않는다.
- **내린 결정·실행:** 부분 TRT와 효과가 확인된 head 최적화를 채택하고, 이득이 없던 topk는
  채택하지 않았다. raw tensor 완전 동일성과 실제 AP 보존을 구분해 평가했다.
- **결론의 경계:** 60.34ms는 해당 GPU·측정 범위의 평균이다. 최대 지연이나 ROS 전체
  센서 age가 아니고 실차·모든 PC의 16.6Hz 보장도 아니다. 미세한 AP 상승은 능력 향상으로 해석하지 않는다.
- **대학원 어필:** profiling–구현–정확도 재평가–복귀 비교로 이어지는 최적화 실험 설계.
- **후속 연구 질문:** 평균뿐 아니라 tail latency·CPU 경합까지 고려한 인지 최적화는 어떻게 할까?
- **근거:** [부분 TRT, 60절](../../docs/bevfusion/evidence/261010_BASE5_INPUT_POOL_OPTIMIZATION_EVIDENCE.md#e12-partial-trt-cuda-experiment-261023),
  [연속 입력, 61절](../../docs/bevfusion/evidence/261010_BASE5_INPUT_POOL_OPTIMIZATION_EVIDENCE.md#continuous-trt-competition-startup-261023),
  [전체 AP, 62절](../../docs/bevfusion/evidence/261010_BASE5_INPUT_POOL_OPTIMIZATION_EVIDENCE.md#head-native-ap-runtime-261023).

## 8. 다른 구현의 25Hz와 우리 결과를 그대로 비교해도 되는가?

- **내 질문:** Jetson에서 나온다는 수치를 더 큰 GPU에서 못 따라가면 구현이 잘못된 것인가?
  backbone·해상도·센서 입력·정밀도·측정 구간이 같은가?
- **내린 결정·실행:** 외부 성능 수치를 목표의 참고로 삼되, 동일 조건의 증거로 취급하지 않았다.
  camera 부분 비용·모델 실행·전처리 포함 서비스·ROS 입출력 지연을 나누어 측정했다.
  CPU 사용량이 늘어나는 미세한 전처리 속도 이득은 풀스택 경합 때문에 채택하지 않았다.
- **결론의 경계:** GPU 성능이나 단일 구간 지연만으로 전체 주행 처리율을 설명하지 않는다.
- **대학원 어필:** 공정한 성능 비교와 시스템 수준 병목 해석.
- **후속 연구 질문:** 제한된 자원에서 인지 정확도·freshness·처리율의 Pareto 경계를 어떻게 구할까?
- **근거:** [측정 범위·CPU 후보, 60~61절](../../docs/bevfusion/evidence/261010_BASE5_INPUT_POOL_OPTIMIZATION_EVIDENCE.md#continuous-trt-competition-startup-261023).

## 9. Sunny13에서 잘 읽는 신호등은 다른 날씨·각도에서도 믿을 수 있는가?

- **내 질문:** HSV와 한 환경 학습만으로 색·화살표가 안정적인가? 검출 박스가 많아지면
  어느 것이 우리 미션 신호인지도 별도로 해결해야 하지 않는가?
- **내린 결정·실행:** YOLO 검출·CNN 점등 판독·지도 기반 미션 선택을 분리하고,
  날씨·시간·시점 변화와 실제 신호 상태를 대조했다. 화면의 비미션 신호도 검출 학습과
  미션 의사결정에서 역할이 다르다는 점을 반영했다. C의 두 physical head는 같은 미션,
  옛 D-1은 비미션으로 구분했다.
- **결론의 경계:** 각 모듈의 성공률과 end-to-end 성공률은 다르다. 가시 영역 밖·너무 작은
  신호·판독 불가를 임의의 색 정답으로 만들지 않고, 튜닝에 사용한 시험은 개발 자료로 취급한다.
  YOLO·매칭·CNN 정확도100%를 주장하지 않는다.
- **대학원 어필:** 분포 변화와 조건부 모듈 평가, 의미·공간 정보를 결합한 문제 분해.
- **후속 연구 질문:** 가시성·선택 불확실성·색 판독 불확실성을 어떻게 분리해서 전달할까?
- **근거:** [신호등 평가·학습 경계 및 운영 한계](../../docs/perception/traffic_light/CURRENT.md).

## 10. 데이터는 많이 모으는 것보다 어떤 것을 어떻게 모으는지가 중요하지 않은가?

- **내 질문:** 날씨·시간·거리·객체 분포가 치우친 데이터에서 수량만 늘려도 되는가?
  native GT와 학습용 박스 표현이 다르면 정확한 라벨이라고 할 수 있는가?
- **내린 결정·실행:** Sunny/Foggy×11/13/15시의6환경과 장애물 보강을 구성해 총30,750프레임,
  train26,136/val4,614로 연결했다. 원래 asset·component·GT 의미를 보존하고 upright7D와
  학습3클래스 변환은 파생 정책으로 관리했다. 선택 ledger·분할·입력 해시를 기록했다.
- **결론의 경계:** 합성 데이터 구축은 실세계 일반화 증명이 아니다. 환경이 여러 개라는
  사실만으로 unseen-domain 평가가 되지 않는다. JPEG는 손실 압축이며 PNG와 동일하지 않다.
- **대학원 어필:** 데이터 생성·표현·품질·재현성을 함께 설계한 data-centric 접근.
- **후속 연구 질문:** 어떤 정보 조건의 데이터를 추가해야 한정된 수집 예산의 효과가 큰가?
- **근거:** [데이터 구성·GT 계약](../../dataset/morai_od/docs/BASE5_V2_CURRENT.md).

## 11. 주행 실패가 알고리즘 때문인가, 입력 지연·좌표·CPU 부하 때문인가?

- **내 질문:** 로컬 MORAI와 풀스택이 자원을 경쟁하는데, 관측된 흔들림·정지를 그대로
  모델이나 판단의 문제라고 결론내려도 되는가? LAN이면 시간 문제는 사라지는가?
- **내린 결정·실행:** native 위치·GNSS·추정 위치의 상대 지연과 좌표·heading 계약을
  대조하고, 경량 GT 시험과 실제 인지 시험을 구분했다. GNSS 보상은 모든 PC에 하나의
  상수를 고정하기보다 기본0ms·명시적 인자로 선택하고 환경별 측정 절차를 마련했다.
- **결론의 경계:** native 상태에 대한 상대 지연이 모든 센서의 절대 시간 오차는 아니다.
  CPU 부하는 중요한 교란요인이지만 모든 실패를 설명하는 면책 사유도 아니다.
- **대학원 어필:** 시계·좌표·측정 구간·자원 경합을 포함한 원인 분리와 실험 통제.
- **후속 연구 질문:** 비동기·지연 변동을 모델링한 센서 융합과 온라인 지연 추정은 가능한가?
- **근거:** [측위 계약·선택적 지연 보상](../../docs/localization/COMPETITION_LOCALIZATION_CURRENT_STATE.md),
  [평가 GT 좌표 계약](../../docs/bevfusion/GT_EVALUATION_COORDINATE_CONTRACT.md).

## 12. 지도를 알고 있다는 사전지식은 얼마나 강하게 사용해도 되는가?

- **내 질문:** NPC가 차선을 따르는 환경에서 Map-CV를 적극 활용할 수 있지 않은가?
  비슷한 confidence의 두 경로 중 top1이 실제 정답이라는 보장은 있는가?
- **내린 결정·실행:** 로터리와 고주로의 예측 목적·길이·후보 정책을 구분했다. 갈림길에서
  점수0.502/0.498이 실제 갈래의 확정 확률이 아님을 확인하고, 고주로의 차선 유지·늦은
  분기 선택을 허용한다는 팀 운영 가정에 맞춰 정책을 정리했다. 지도 종단은 가용 구간을
  출력하는 것과 지도 정합 실패 후 운동 모델 fallback을 구분했다.
- **결론의 경계:** 대회의 고정 지도·NPC 행동 가정은 일반 도로에서의 예측 정당성이 아니다.
  길게 예측하는 것 자체가 정확도·안전성 향상은 아니며, 다중 경로의 소비 방식도 확인해야 한다.
- **대학원 어필:** 모델 점수·지도 사전지식·과제 가정을 구분하고 downstream 요구와 조율한 경험.
- **후속 연구 질문:** 구조적 사전지식과 불확실한 행동 분기를 어떤 표현으로 함께 전달할까?
- **근거:** [지도 경로·종단·고주로 정책](../../base_ws/src/perception_object_pipeline/docs/TRACKING_PREDICTION_CURRENT.md),
  [동일 트랙의 운동 모델 비교, 65절](../../docs/bevfusion/evidence/261010_BASE5_INPUT_POOL_OPTIMIZATION_EVIDENCE.md#e12-map-motion-ablation-261023).

## 대학원 지원에 우선 사용할 세 가지 이야기

1. **정보 부족을 데이터 부족과 구분했다.** LiDAR0점·희소점·거리별 분석을 통해
   추가 수집의 효과와 한계를 나누고, 무작정 수집하는 방향을 더 밀지 않았다.
2. **높은 AP와 안정적인 주행은 다르다는 질문을 던졌다.** 시간적 일관성을 개선하면서
   실제 움직임에 대한 반응 지연은 늘리지 않는 문제로 확장했다.
3. **정확도와 속도를 함께 검증했다.** 부분 TRT·SDPA를 국소 비용뿐 아니라 전체 val과
   연속 입력에서 비교하고, 이득이 없는 후보는 채택하지 않았다.

지원 분야는 강건한 멀티모달3D 인지, 시간적 일관성·불확실성, 실시간 로봇 인지와 연결된다.
각 이야기는 ‘질문 → 비교 조건 → 결과 → 선택 → 반례·한계’ 순서로 설명한다.

## 표현·증빙 체크리스트

- 30,750은 멀티센서 **합성 프레임 수**다. 실세계 이미지 수로 바꾸어 쓰지 않는다.
- AP는 이 프로젝트의 중심 거리 기반 평가다. 검출 정확도·공식 nuScenes 점수와 혼용하지 않는다.
- E24→E12의 데이터·학습 등 변화가 함께 있으므로 데이터 증가만의 인과효과를 주장하지 않는다.
- 동일512프레임 원거리 subset과 전체4,614프레임 val 결과를 섞지 않는다.
- 조건부0점 적중0%와 camera-only 불가능을 동일시하지 않는다.
- 서비스 평균·GPU 구간·ROS/LAN 지연·실제 처리율을 구분한다.
- 추가 시간 조건을 없앴다는 것과 전체 인지 latency0을 구분한다.
- 알려진 지도·NPC 가정과 새 환경의 일반화 검증을 구분한다.
- 팀·AI 도구를 활용한 구현에서 개인이 담당한 문제 정의·설계 선택·분석·검증 범위를 설명한다.
- Innovation Award는 사용자 보고 수상 사실이다. 약6/34 순위는 추정이므로 공식 확인 전 확정 표기하지 않는다.
- 대회에서 인지가 잘 작동했다는 관찰과 모든 인지 오류가 없었다는 인증을 구분한다.
- 이 회고의 요약은 상세 실험의 대체물이 아니다. 지원서 수치에는 원래 조건과 근거를 함께 둔다.
