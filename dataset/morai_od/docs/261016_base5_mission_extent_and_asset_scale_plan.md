# Base5 정적 미션 범위와 장애물 크기 다양화 계획

문서 상태: PLAN. 기준일: 2026-10-16, Asia/Seoul.
현재 데이터·검증 상태는 [Base5 CURRENT](BASE5_V2_CURRENT.md)를 따른다.

후속 주석(2026-10-17): 아래 확대 계획은 실험 이력이다. 혼합 native 치수 변동이 재현되어
확대 수집을 중단하고 다음 수집은 원형으로 준비한다. 정적 구역 확장은 유지하며
[10/17 최종 판정](261017_base5_scale_split_qualification.md#확대-수집-중단과-다음-원형-경로)이 우선한다.

새 5K를 만들기 전에 정적 미션의 삼거리 통과 후 배치를 보강하고, 문맥상 자연스러운 장애물의
크기 변화를 생성기에 통합한다. 후보 자산·배율·장수는 실제 소량 캡처를 보고 결정한다.
이번 학습이 끝난 뒤 채택 여부를 판단하는 계획이 아니다.

기존 Sunny13 5K·E24·v154 source와 release는 보존한다. v154는 당시 scale 1 계약의 검증 결과다.
새 요구사항의 검증과 별도 동결 전에는 새 본수집을 보류한다. 이 계획 문서화만으로 수집기 코드나
과거 release JSON의 `bulk_ready`를 변경하지 않는다.

## 유지할 배치와 학습 계약

- 총 장면은 새 5K다. 별도 확대 장애물 묶음을 뒤에 추가하는 방식이 아니라 생성 단계부터 통합한다.
- 정적 미션은 일반 차량·OBJ 차량·사람·동물·복합체 등 허용된 전체 객체군을 유지한다.
  구간 이름의 ‘장애물’과 학습 클래스 Obstacle을 동일하게 취급하지 않는다.
- 동적 미션에는 정적 Obstacle 자산을 움직이는 예외를 넣지 않는다. 기존 두 횡단보도 경로와
  출발→도착 두 waypoint·높이 lookup을 유지하고 새로운 이동 구역은 우선 추가하지 않는다.
- Ego의 연속 도로 위치 샘플링, 근거리 장애물·원거리 차량 보강, 정지 yaw·방향·미션 phase·split·희귀 자산 coverage를 보호한다.
- 이미지 512×1056·Q90·native GT·upright 변환·클래스 매핑과 모델 구조는 이번 작업에서 변경하지 않는다.
- 지면·간격·가시성·실제 이동·Ego 정지·CollisionData·종료 Park 검사와 유한 보충은 유지한다.

## 정적 미션의 공간 범위

사용자가 제공한 미션 지도는 정적 구간을 삼거리 전후로 표시한다.
현재 v154 정적 미션 600장의 주요 객체를 MGeo 경로에 투영하면 다음과 같다.

| 위치 | 현재 장면 수 | 재배분 시작안 |
|---|---:|---:|
| 삼거리 진입 전 | 440 | 300 |
| 삼거리 안쪽 | 160 | 120 |
| 삼거리 통과 후 | 0 | 180 |
| 합계 | 600 | 600 |

현재 주요 객체의 경로 진행거리는 약 250.0–341.2m이고, 삼거리 직진 connector는
`A2256W000222`의 약 316–347m 구간이다. 통과 후 `A2256W000220`·`A2256W000202`에는
정적 미션 주요 객체가 없다. 주변 범용 사례는 있으므로 완전한 학습 공백이 아니라 미션 저격의 공백이다.

첨부 그림에는 지리 좌표가 없으므로 녹색 박스 끝점을 정확한 지도 경계로 단정하지 않는다.
삼거리 전·안·후의 도로 link와 허용 구간을 먼저 대응하고, 실제 배치 가능성과 영상 배경을 확인한다.
초기 240/180/180안은 기존 물리 link 기준 split과 맞지 않아 300/120/180으로 조정했다.
삼거리 안쪽 link가 val이고 기존 정적 미션 val은 156장이므로, 안쪽 180장을 요구하면 split을 깨게 된다.
수정안은 train 444·val 156을 유지하고 통과 후에 train 144·val 36을 배분한다.
이는 coverage를 위한 시작안이지 공식 출제 확률이나 확정 quota가 아니다.
기존 122종 primary와 회피 접근·진입·측방·이탈 phase, BBox 경계 간격, yaw·split을 함께 층화한다.
Ego가 통과 후에 있다는 이유만으로 주요 객체도 해당 구간에 배치됐다고 집계하지 않는다.

신호등 인지와 회피의 상호작용은 이번 OD snapshot 배치의 제약으로 추가하지 않는다.
공식 답변은 폐루프 주행 시나리오의 설계 의도로 보존하고, 객체의 허용 위치를 좁히는 근거로 사용하지 않는다.

동적 미션은 현재 두 횡단보도와 접근 20–50m·횡단 8–20m·양보 5–10m·통과 후 6–15m 관측을 유지한다.
새 객체 이동 경로를 만드는 것과 기존 경로를 다른 Ego 위치에서 보는 것은 구분한다.
이 선택은 사거리 밖 동적 출제가 불가능하다는 보장이 아니라 검증 비용과 예상 분포를 고려한 우선순위다.

## 크기 변형의 근거와 시험 후보

[원본 대회 샘플](../../../configs/scenario/2026_molit_comp_sample_scene.json)의 CargoBox에는 scale `(2,3,2)`가 있다.
현재 v154의 `objectList` 부모 4,328개는 모두 `(1,1,1)`이다. 크기 다양화가 이미 수집된 상태는 아니다.
[공식 질답 기록](260920_questions_for_morai.md#gt와-충돌-형상)에 따르면 scale은 그래픽·물리에 반영되지만
`/Object_topic.size`는 기본 자산 제원이다. 본선의 정확한 배율·빈도가 확정된 것은 아니다.

크기 변경은 실제로 다른 규격 제품이라고 받아들일 수 있는 자산만 대상으로 한다.
아래는 캡처 시험 후보이며, 표에 있다는 이유로 본수집에 자동 포함하지 않는다.

| 자산군 | 시험할 변화 | 외형 검토 기준 |
|---|---|---|
| CargoBox | 등방 1.25–2배와 샘플 `(2,3,2)` 같은 제한적 비등방 확대 | 큰 운반 상자로 자연스럽고 부속 구조·비율이 어색하지 않은가 |
| WoodBox | 상자 규격 변화 | 확대 후 외형과 기존 mesh·LiDAR·BBox 정합 문제가 없는가 |
| PE 방호벽·철제 및 콘크리트 바리케이드 | 길이 위주 확대, 높이·두께 변화 제한 | 다른 규격의 공사 방호물처럼 보이고 지지부·패턴이 어색하지 않은가 |
| RedBarrel·YellowBarrel·TrafficBarrel·PE_Drum | 등방 1.2–1.5배부터 시험 | 다른 용량의 통으로 자연스럽고 과도하게 거대하지 않은가 |
| 볼라드·차선 분리봉 | 크기 변형 제외 | 기존 규격과 거리 정책 유지 |
| 차량·차량형 OBJ·사람·동물·유모차·복합체·탑승자·자전거·스쿠터 | 크기 변형 제외 | 정적 배치 포함 여부와 크기 변형 허용 여부를 구분 |

배율은 탐색 시작점이다. 최종 실물 치수와 영상이 부자연스러우면 수치 검사를 통과해도 기각하거나 줄인다.
반대로 자연스럽다는 인상만으로 LiDAR·GT 정합 검사를 생략하지 않는다.
큰 물체가 무조건 좋은 것이 아니며, 가림·과밀로 다른 객체의 유효 노출을 줄이는지도 확인한다.

## 소량 캡처에서 결정할 내용

첫 시험은 대표 6–8종·16–24장 정도로 시작하되 필요한 비교 조건에 따라 조정한다.
동일 자산의 scale 1 대조군, 확대 조건, yaw 0/90도와 근·중거리 조건을 의도적으로 배치한다.
CargoBox의 샘플 scale도 포함한다. 모든 조합을 첫 시험에 억지로 넣기보다 문제 조건을 후속 시험한다.

1. 원본 이미지·crop과 LiDAR/GT overlay를 직접 보고 실제 도로 문맥에서 자연스러운지 판단한다.
2. Unity 로컬 scale 축과 실제 native 치수·pivot 이동을 대조한다. ROS length/width/height에
   같은 순서로 곱한다고 가정하거나 margin을 포함한 annotation이 정확한 배율이 된다고 가정하지 않는다.
3. 확대된 footprint·회전·pivot을 반영한 초기 높이, 지면 접촉, Ego/객체 간 간격을 확인한다.
4. native annotation의 중심·치수·회전과 실제 영상·LiDAR 형상을 대조하고 512 crop·XYZ ROI 영향을 확인한다.
5. 실제 native GT를 Q90/upright/현재 클래스의 학습 입력으로 변환해 잘못된 제외·이중 scale 적용이 없는지 검사한다.
6. 가까운 큰 장애물 둘에 대해 가림과 중복 억제의 영향을 별도로 확인한다. 학습된 E24 출력을 사용하더라도
   새 scale 데이터로 학습한 성능이라고 해석하지 않는다.

조건별 원본·scale·최종 치수·접지·간격·센서 지원·변환 결과와 함께, 외형 판단의 채택/축소/기각 사유를 남긴다.
실패 원본도 보존하고 QA 완화로 후보를 통과시키지 않는다.
자산별 허용 목록과 배율은 이 캡처 검토에서 확정하며 본수집·재학습 이후로 결정을 미루지 않는다.

## 생성기와 복구 경로에 통합

자산별 정책에 크기 변형 허용 여부, 허용 축·비율, 최종 실물 치수 범위와 선택 비중을 기록한다.
생성기가 원래 자산을 선택한 뒤 해당 정책 안에서 기본/변형 크기를 결정하고, 배치 전에 크기를 적용한다.
선정된 사례만 사후 JSON scale을 바꾸는 방식은 사용하지 않는다.

확대 size·pivot offset·높이·footprint를 간격·도로 지지·가림·객체 수 budget 계산에 반영한다.
scale 1 전용 높이 cache·형상 reference와 작은 primary 거리 상한은 그대로 재사용하지 않는다.
scale별 근거를 분리하고 실제 크기와 센서 지원에 맞춰 거리 정책을 검토한다.
raw scenario와 metadata에 scale·정책·선택 근거를 기록하고, 학습 GT는 native annotation에서 가져온다.
이미 확대된 native GT에 scale을 다시 곱하지 않는다. rosbag 평가가 필요하면 기본 `/Object_topic.size` 대신
scenario scale sidecar 또는 검증된 센서 근거를 사용한다.

초기 120장 예산은 폐기하고 자산을 선택한 뒤 box는 30%, barrier·drum은 20%를 변형하는 시작안을 사용한다.
실제 채택 배율만 이산적으로 선택하며 연속 jitter는 넣지 않는다. 자산·split별 원형 사례와 primary를 보호한다.
v154의 후보 12종 전체가 승인된다고 가정하면 변형 가능 부모는 2,668개이고, 독립 actor 선택의 기대치는
약 581개 부모·486장이다. 이는 정책 비교용 기대값이며 native 검증이나 최종 배분 결과가 아니다.
실제 채택 자산·센서 지원·자연스러움에 따라 조정하고 기존 규모·coverage·거리·방향·split을 보존한다.
후속 단독 대조에서 8종·16개 규격을 승인했지만, 혼합 장면에서 RedBarrel의 실측 기본 치수가 달라져
그 확대만 보류했다. 현재 통합 후보는 7종·14개 규격, 315장·361개 변형 부모다.
원형 RedBarrel은 유지한다. 위 12종 기대값을 채택 장수로 사용하지 않는다.
[실측 근거](261016_base5_native_scale_and_extent_evidence.md)의 원형/변형 대조와 전체 생성 결과를 따른다.
보충·재배치도 같은 자산별 크기 정책을 따라야 하며 실패 후 몰래 scale 1로 바꾸지 않는다.
허용된 변경은 새 mapping에 남기고 quota 변경도 명시적으로 감사한다.

BEV 전체 scale 증강은 개별 물체의 mesh·영상 비율·가림·LiDAR 회신을 바꾸는 수집을 대체하지 못한다.

## 실행 순서와 본수집 준비 완료 조건

1. 미션 지도와 MGeo의 허용 구간을 대응하고 정적 전/안/후 배분 후보를 만든다.
2. 확대 배치에 필요한 size·pivot·높이·cache·budget 계산을 새 정책으로 준비하고 CPU 회귀를 검사한다.
3. 독점 MORAI 통제권·센서·통신·annotation 저장을 확인한 뒤 소량 캡처와 외형/센서 검토를 반복한다.
4. 채택한 자산·배율·비중을 생성기에 통합하고 새 5K 전체를 새 경로에 생성한다.
5. 구간별 Ego/주요 객체 위치, 자산·scale·실물 치수, 거리·방향·회피 phase·yaw·split·중복·예상 GT를 감사한다.
6. 대표 미션·크기 변형·기존 이동 및 원거리 보호 사례를 native 검증하고 부분/완료 resume와 유한 보충을 확인한다.
7. 실제 새 비용으로 5K 시간·디스크를 다시 추정하고 source/runtime/검증 근거를 별도로 동결한다.

새 자산별 크기 정책과 확장된 정적 미션 범위가 검증되기 전에는 본수집 준비 완료로 표시하지 않는다.
현재 v154의 `bulk_ready=true`나 8–12시간 예산을 새 정책의 승인·실측값으로 승계하지 않는다.
2026-10-16 최종 v155m은 native 17/17·변환·재개·CPU 회귀를 통과했다. 본수집·학습은 하지 않았다.
현재 Sunny13 본수집 실행과 자동 보충의 미승인 범위는 [최종 근거](261016_base5_native_scale_and_extent_evidence.md)를 따른다.
첫 CargoBox 축 분리 시험에서는 시각적 확대와 달리 native 3D annotation의 size가 원형에 고정되는 현상을 확인했다.
이는 요약 Instance size의 문제였으며 동일 시각의 원본 8Points에는 실제 모서리가 있었다.
후속 [native 근거](261016_base5_native_scale_and_extent_evidence.md)에서 등록된 변형만 원본 모서리를 검증해
크기를 얻도록 구현했다. 초기 발견은 이력으로 보존하며 최종 준비 상태는 CURRENT를 따른다.
